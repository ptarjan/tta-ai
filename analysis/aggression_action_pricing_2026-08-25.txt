CONFIRMED (part 1 of the question): every Aggression card except Enslave prints
an all-zero CardEffects block -- every field that carries a printed number is 0
-- and its entire value lives in `special`. card_yields (cards.rs:223) has a
dedicated Aggression-only pricer (`aggression_value`, gated by
AggressionBoardCredit, card_potential_core dispatch at cards.rs:2006-2010) but
when that credit is 0.0 the function falls through to the generic tail
(cards.rs:2053), which walks `card.special` through a giant match
(cards.rs:398-462) that is exhaustive over every `Special` variant. Every
variant these 10 cards use -- TakeFromOpponent, DestroyUrbanBuildings,
GainResources, StealColony, ColonyPermanentBonusTransfers, RemoveFromGame,
GainCulturePerLevelOfRemovedCard, OpponentDecreasesPopulation -- is listed on
the right-hand side of that match's single no-op arm (cards.rs:462). None of
these ten push a single WeightKey. That is exactly the Event-shaped blackout
the background flagged: 10 no-op'd cards.

Enslave is the one exception because, unlike the other ten, it ALSO carries
nonzero numeric CardEffects fields (gain_food:2, gain_resources:2) alongside
its Special (OpponentDecreasesPopulation, itself no-op'd). Those two fields are
pushed unconditionally by card_yields' generic `_EFF_TO_FEATURE` block
(cards.rs:288-289) as `(WeightKey::FoodStock, 2, Gain)` and
`(WeightKey::ResourceStock, 2, Gain)`.

Code trace (card_potential_core, cards.rs:1960-1964 dispatch, then the shared
tail at cards.rs:2053-2068 when ActionBoardCredit==0.0):

  1. card_yields (cards.rs:223) never pushes `resource_discount` or
     `resources_for_military_units` -- DELIBERATELY (cards.rs:334-357 comment):
     they are reserved for action_value's board-aware resource_stock marginal.
     The comment documents a real prior measurement: on the live 2p champion, a
     flat push priced Rich Land (A)'s resourceDiscount at 0.0 (dominance_repair
     clamps the persisted negative resource_discount weight to 0.0, a
     BENEFIT_GATES member) versus 1.82 through the board-aware marginal -- the
     static formula was PROVEN wrong, not merely unused.
  2. `Special::FreeCivilAction` is also deliberately no-op'd in card_yields'
     special match (cards.rs:416-429 comment): it used to be a flat +1.0 gain,
     a second formula disagreeing with action_value's own board-aware
     free_action_credit marginal for the same 18 action cards; the flat
     version and its WeightKey::FreeCivilAction coordinate were retired
     outright.
  3. board_extra (rust/src/bots/board_yields.rs:908-940) fires independently of
     ActionBoardCredit (gated on `credit_board = card_board_credit +
     board_credit_key(id)`, and board_credit_key returns None for
     CardType::Action -- so credit_board is just card_board_credit, which is
     nonzero at 4p). It only recognizes two Special variants:
     CulturePerCivilizationWithMoreCulture (counts rivals with more culture)
     and ResourcesForMilitaryUnitsPerStrongerCivilization (counts rivals
     stronger than you); it does NOT recognize FreeCivilAction or read
     resource_discount at all.
  4. card_choice (cards.rs:504) is a separate, dedicated hook for
     GainFoodOrResources, applied at cards.rs:2061-2063 gated on `base`
     (card_board_credit) -- NOT on action_board_credit -- so Reserves (I/II/III)
     is priced through it regardless of whether action_value ever runs.

  So the 15 zero-priced cards split into two different causes:
    - 13 of them (Rich Land x3, Urban Growth x4, Engineering Genius x4,
      Efficient Upgrade x2) have NO other numeric lever at all: their only
      printed value is resource_discount + FreeCivilAction, and both are
      wired EXCLUSIVELY to action_value. With action_board_credit clamped to
      0.0, nothing in the fallback chain (card_yields / card_choice /
      board_extra) reads either field. This is unconditional -- true on every
      board state, not just this one.
    - 2 of them (Wave of Nationalism, Military Build-Up) DO reach board_extra
      (their special IS one of the two board_extra recognizes), but on this
      specific deterministic baseline no rival's strength exceeds the pricing
      player's, so the `if n > 0` guard at board_yields.rs:935 suppresses the
      triple -- a genuine, board-aware zero for this state, not a dead code
      path. (Consistent with Endowment for the Arts landing nonzero at 3p/4p
      but exactly 0.0 at 2p in the same table -- board_extra's other branch,
      same `n > 0` guard, evaluating true or false depending on how many
      rivals currently have more culture than the player on that baseline.)

  The 18 nonzero cards all reach a live path regardless of action_board_credit:
  a flat CardEffects gain that card_yields' generic `_EFF_TO_FEATURE` block
  always pushes (gain_food/gain_resources/gain_culture/gain_science/
  military_actions -- Frugality, Patriotism, Cultural Heritage, Stock Pile,
  Breakthrough, Revolutionary Idea), or card_choice's GainFoodOrResources hook
  (Reserves I/II/III), or board_extra's CulturePerCivilizationWithMoreCulture
  branch (Endowment for the Arts, board-state-dependent as above). Patriotism
  prices IDENTICALLY (0.817829) across all four ages A/I/II/III despite its
  printed resources_for_military_units growing 1/2/3/4 -- confirms that field
  is never read; the constant price is purely `1 * w[military_actions]`
  (military_actions:1 is the same on every Patriotism copy), independent of
  age.

=============================================================
VERDICTS
=============================================================

VERDICT -- Aggression @3p and @4p: (b), inherently board-relative, no code
fix warranted.
  All ten no-op'd cards are, without exception, effects that are only
  meaningful relative to an OPPONENT's current board state: TakeFromOpponent
  (worth 0 if the opponent lacks that resource/science/culture), Destroy
  UrbanBuildings + GainResources (worth 0 if the opponent has no matching
  building, and its size depends on what they built), StealColony (worth 0 if
  the opponent has no colony to steal), RemoveFromGame + GainCulturePer
  LevelOfRemovedCard (value depends on the level of whatever gets removed).
  There is no rulebook-guaranteed flat fact any of these cards carries the way
  an Event's "level = guaranteed culture on prepare" fact does -- this is
  exactly War's shape (dedicated `aggression_value`/AggressionBoardCredit
  pricer already exists for precisely this reason, mirroring `war_hand_value`/
  WarBoardCredit), not Event's. The only lever is the trained credit itself:
  it is currently negative at both 3p and 4p and gets clamped to 0.0 by
  dominance_repair (a printed benefit may never price negative), so the
  dedicated pricer never runs and everything but Enslave (which happens to
  carry genuine unconditional numeric fields) reads 0.0. That is a training
  outcome, not a coding gap.

VERDICT -- Action @4p: (b), inherently board-relative, no code fix
warranted.
  The systematic component of the 15 zero-priced cards (13 of the 15: Rich
  Land / Urban Growth / Engineering Genius / Efficient Upgrade) is driven
  entirely by resource_discount and FreeCivilAction, and the code comments at
  cards.rs:334-357 and cards.rs:416-429 show this was already tried the other
  way and reverted: a flat, static push of resource_discount measurably
  disagreed with the board-aware marginal on a live champion (Rich Land (A):
  0.0 static vs 1.82 board-aware -- the static number was simply wrong,
  because a resource discount's worth depends entirely on what the player is
  about to build, and a free civil action's worth depends on the board's
  current marginal value of a civil action). Both fields are deliberately
  reserved for action_value alone. This is the same shape as War/Aggression,
  not Event -- there is no honest flat proxy, so the cure is
  action_board_credit training away from 0.0, not a code change. (The
  remaining 2 of the 15 -- Wave of Nationalism, Military Build-Up -- are
  already board-aware-correct zeros for this specific baseline via
  board_extra, independent of ActionBoardCredit, and are not part of this
  gap at all.)
