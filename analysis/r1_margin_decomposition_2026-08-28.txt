THE ~38 MISSING POINTS: ROOT CAUSE (CONFIRMED, gap 0.000000000)
---------------------------------------------------------------
The earlier job-J analysis (and the first draft of this dump) scored EndTurn on the
UNMOVED root + end_turn_bias, mirroring WeightedBot::choose (eval.rs:493-499). That is
WRONG for the measured ground truth, which is read off WeightedBot::rank_moves.

rank_moves (eval.rs:546-553) APPLIES every candidate -- INCLUDING EndTurn -- before
scoring:
    for &mv in moves {
        let mut trial = root.clone();
        apply::apply(&mut trial, mv);          // <-- EndTurn IS applied here
        let mut val = evaluate(&trial, idx, w, Some(&ctx), None);
        if matches!(mv, Move::EndTurn) { val += end_bias; }
        ...
    }
apply.rs:314:  Move::EndTurn => crate::game::end_turn(state)
So EndTurn is scored on the END-OF-TURN state: production collected, civil/military
pools debited-then-refilled, turn advanced, age checked. choose skips the apply for
EndTurn (it would otherwise double-count production); rank_moves does not. The two
bots therefore price EndTurn differently by design, and the measured margin uses
rank_moves.

WHY ENDTURN WINS AT ROUND 1 (the answer)
----------------------------------------
At the first round-1 decision the board is near-empty, so the Take's own value
(HandPotential +3.0 to +13.5, plus small TakeCostShare/CaLeft/HandValue terms) is
small. But rank_moves' EndTurn candidate has ALREADY collected the turn's production
(Workers -30.2, FoodStock -1.9, ResourceStock -1.3, Science -0.5, CivilActionSurplus
-6.2 -- all the stocks/gaps EndTurn's apply realizes) before it is scored. The Take
candidate does NOT get that production yet (it is still mid-turn). So EndTurn is
credited ~30-40 points of production the Take has not earned, and wins. The single
dominant term is Workers (-30.17), the phase-blended workers key at workers_late=106.18.

This is a RANKING artifact of rank_moves' apply-EndTurn convention (deliberate, to
avoid double-counting production the way choose guards against), not a feature-vector
error: every per-term contribution sums to the measured margin to 1e-9.
