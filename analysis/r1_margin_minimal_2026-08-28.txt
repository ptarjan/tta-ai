STEP E: WHAT THE THREE ROW KEYS COMPUTE
------------------------------------------
All three are linear multiplier terms: eval::evaluate() gates each behind
`w.get(WeightKey::X) != 0.0`, then does `total += weight * <scalar>`, exactly
like every other priced-through-w feature in that block (rust/src/bots/
weighted/eval.rs:372-388). The "f.set" site -- where the raw, w-independent
feature values are written into the shared feature vector `out[]` for
credit-assignment/regression purposes, separate from evaluate()'s pricing --
is features.rs's features() fn at eval.rs:685-688:
    let (row_urgency, row_bargain) = row::row_pressure(state, idx, freeze, ctx);
    out[WeightKey::RowUrgency as usize] = row_urgency;
    out[WeightKey::RowBargainForgone as usize] = row_bargain;
    out[WeightKey::RowLastCopy as usize] = row::row_last_copy(state, idx, freeze, ctx);

RowUrgency (rust/src/bots/weighted/row.rs:312, row_pressure()):
  Sum of card_potential() over visible card-row slots that are about to
  slide off the row entirely this action (no swap slot available, i.e. the
  card is gone for good if not taken now) -- the "value about to vanish"
  half of row_pressure's (urgency, bargain) pair (row.rs:352-381).

RowBargainForgone (row.rs:312, same row_pressure() call, second return
  value "bargain"):
  For row slots that WILL still be reachable after sliding (cost strictly
  decreases as the slot advances, `saving > 0`), the value forgone by not
  waiting for the discount, discounted by how much rival players are
  competing for that same slot (rival_desire/rival demand modeling,
  row.rs:383-420ish). Roughly: "what taking early costs you vs. waiting."

RowLastCopy (row.rs:475, row_last_copy()):
  A deterministic, w-INDEPENDENT count of wanted slots (card_potential > 0
  used only as a boolean gate, never as a magnitude) that are about to
  disappear for good with no further copy expected in the deck this age
  (civil_outlook-based P(no further copy), row.rs:440-444). The doc comment
  at row.rs:446-465 records this was a deliberate "UNITS FIX": it used to
  multiply card_potential's own w-priced magnitude by rlc's coefficient a
  SECOND time, which meant rlc's fitted value drifted whenever any other
  weight in `w` moved. Now it prices a fixed quantity (count of doomed
  wanted cards) so rlc means "price per about-to-vanish wanted card" at
  every position.

All three read board/row state through `w` (card_potential, competition
modeling) but are themselves priced linearly via w.get() as a scalar
multiplier on a row-pressure/timing signal -- not a *BoardCredit-style
per-yield linear feature. Preclimb -> postclimb all three collapsed toward
zero (row_bargain_forgone 2.18 -> 0.12, row_last_copy -0.24 -> 0.006,
row_urgency -0.58 -> -0.16), i.e. the champion nearly stopped pricing
row-timing pressure at all, which tracks with ROW being the dominant family
in the leave-one-family-out ranking and the clearest single-family control
beat here.
