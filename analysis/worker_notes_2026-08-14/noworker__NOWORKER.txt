STEP 4: hand-traced 7523355 -- found and fixed a REAL, NEW bug
============================================================

Full ledger walk for Orange (2p game) from round 1 through the failure
(round 13, "Orange builds Religion", workers_free=0) is internally
consistent for every Build/BuildUnit/BuildWonderStage/Upgrade/Colonize
action EXCEPT one: round 11's "Immigration" event --

  "Orange plays event ... Current event:; I / Immigration; All
   civilizations with the most happy faces gain 1 population.; Orange
   receives a new immigrant; Purple receives a new immigrant"

Both players are NAMED in the journal as receiving a population token. The
engine's own `workers_free` trace shows NO change across this event for
Orange (stayed at 1 both immediately before and immediately after). Added a
temporary `TMPDEBUG_TIED` probe (gated behind `REPLAY_DEBUG_ALL`, REVERTED
before the final commit) to `events::apply_tied_targets` and confirmed:
`stat=Happy top=0 values=[0, 0]` -- BOTH players are tied at 0 happy faces,
and `apply_tied_targets`'s own gate (`if top <= 0 { return; }`) skipped the
grant for EVERYONE.

Root cause: `apply_tied_targets` is the SHARED implementation for BOTH
`Special::PlayersWithMostHappyFaces` (Immigration) and
`Special::PlayersWithMostDiscontentWorkers` (a different card, e.g. the
`blue_tokens: -1` one at card_table.rs line 3541), and its "skip when the
tied stat is 0" gate applied to BOTH uniformly. The gate's own doc comment
already explained its ACTUAL justification is Discontent-specific ("'the
players with the most discontent workers' targets nobody when nobody has
one" -- 0 discontent workers means nobody genuinely "has" one), but nothing
in that reasoning applies to Happy faces: everyone tied at 0 happy faces is
still tied for the most happy faces.

RULE CITATION: `docs/RULES_SPEC.md` line 119 (§5.3, "Evaluating events"):
'"All civilizations" with most/least: all tied civs affected, no
tie-break.' -- no positivity clause anywhere in that sentence. Corpus
evidence in the SAME direction: game 7523355's own journal explicitly grants
both tied-at-zero players their immigrant.

FIX: `src/events.rs`, `apply_tied_targets` gained a `require_positive: bool`
parameter. The `RankStat::Happy` call site (Immigration) now passes `false`
(never gates on positivity); the `RankStat::Discontent` call site keeps
`true` (unchanged behavior, preserving the existing, differently-justified
mechanism -- NOT re-verified against the corpus this pass, since Discontent
was explicitly out of scope and untouched).

TEST: `src/events.rs`, `events::tests::
immigration_grants_population_to_both_players_tied_at_zero_happy_faces` --
two blank 2p players (both 0 happy by construction), `resolve_event(&mut
state, card("Immigration"), 0)`, asserts BOTH players' `workers_free` become
1. Confirmed RED by temporarily flipping the Happy call site's new
parameter back to `true` (`cargo test --profile fasttest --lib
events::tests::immigration_grants_population_to_both_players_tied_at_zero_happy_faces`
FAILED, "left: 0, right: 1"), then reverted to GREEN (same test PASSED).

Full suite after the fix: `cargo test --profile fasttest --lib` -> 1409
passed, 0 failed. `cargo clippy --all-targets -- -D warnings` -> clean, no
warnings.

Confirmed 7523355 itself now replays to completion with a matching score:
