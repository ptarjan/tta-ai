ROOT CAUSE #1 (3 of 8 games): phantom corruption charge, one band too high
----------------------------------------------------------------------------
Games 7522024 (round 10, Orange), 7521657 (round 16, Purple), 7521791
(round 7, Green) all show the IDENTICAL shape: the engine's own
`economy::end_of_turn` "pre-corruption" trace computes
`blue_available(p) == 10` (`blue_total - blue_used`), landing in
RULES_SPEC.md's own §6.2 table's "10-6 -> 2" band, and charges 2 corruption
resources that the real BGO journal's own "(now N)" total proves were NEVER
charged (no "CORRUPTION!" line, and the arithmetic only balances with
corr=0). All three cases need `blue_available>=11` (one token less
occupied, or one more in the bank) to reproduce the journal exactly -- an
"off by exactly one occupied blue token" pattern, same direction every
time.

Ruled out as the cause, one at a time, each independently verified against
`card_table.rs` / `docs/RULES_SPEC.md` before moving to the next (mirrors
resshort's own methodology on a fourth, independent game):
  - `blue_total`'s card-driven adjustments are correct: 7522024's Orange
    has colonized "Vast Territory (I)" (`blue_tokens: -1` in card_table.rs,
    confirmed against `sources/bga_throughtheages_material.inc.php`'s own
    printed "-1 blue token" bonus text) -- 16-1=15, matches the trace.
    7521657's Purple has colonized "Developed Territory (I)"
    (`blue_tokens: 1`) -- 16+1=17, matches the trace. 7521791's Green has
    no blue-token-affecting colony -- stays at the base 16, matches.
  - `Denoms::of`'s food/mine denominations are individually correct against
    each player's own `REPLAY_DEBUG_TECHS=1` tech dump (e.g. 7521657's
    Purple: Agriculture(1)+Selective Breeding(3) -> food_denoms=[3,1];
    Bronze(1)+Coal(3) -> mine_denoms=[3,1], both confirmed against
    card_table.rs's own printed `production` values) -- no missing
    denomination that would let `tokens_for`'s greedy algorithm represent
    the same stock with fewer tokens.
  - `tokens_for`'s greedy computation is itself minimal given the known
    denominations (hand-verified: no combination of the confirmed
    denominations represents the confirmed stock in fewer tokens than what
    the trace shows).
  - The corruption band boundary itself (`blue_available>=11 -> 0`,
    `6..=10 -> 2`) is independently confirmed CORRECT elsewhere in the
    corpus: resshort__RESSHORT.txt's own HAND-TRACE 1 (game 7523124, a
    DIFFERENT game) found `blue_available=10 -> corr=2` matching a REAL
    "CORRUPTION! Orange loses 2 resources" journal line at a different
    checkpoint in that same game -- so this isn't a simple off-by-one in
    the `corruption()` function's threshold; something about the
    RECONSTRUCTED state at these specific checkpoints is one token
    different from BGO's own bookkeeping, not the formula.
  - Attempted one deeper lead on 7521791 specifically: traced whether
    Green's farm-card WORKER count (not just denomination) could be wrong
    (Agriculture shows a constant workers=2 across the ENTIRE game,
