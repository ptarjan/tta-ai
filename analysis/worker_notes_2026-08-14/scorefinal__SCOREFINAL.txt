WHAT CHANGED (the only diff in this session's patch)
============================================================================
Two small, env-gated, read-only debug hooks were added, following the EXISTING SCOREDIV_* debugging
convention already present throughout this codebase (SCOREDIV_HAPPY_DUMP, SCOREDIV_POPULATION,
SCOREDIV_EVENT_DEBUG, SCOREDIV_FINISH_GAME, SCOREDIV_DUMP_COMPLETED, SCOREDIV_DUMP_IDS -- all
pre-existing, all landed by prior sessions for the exact same purpose). Both were essential to pin
down 7522864 and 7523162's root causes above and are left in place for whichever session picks those
two back up, exactly as prior sessions left their own diagnostic hooks in place.

1. rust/src/game.rs, `finish_game`: prints each player's `p.culture` immediately before
   `events::evaluate_final_events` runs, gated behind the EXISTING `SCOREDIV_EVENT_DEBUG` env var
   (no new env var). Purely a read of already-computed state; does not touch control flow, scores,
   or any player-visible behavior.

2. rust/src/effects.rs, `compute`: at the very end (after `stats.happy` is clamped, before
   `stats` is returned), prints every entry of `p.techs` (name + worker count) plus
   `p.workers_free`/`p.yellow_bank`, gated behind a NEW env var `SCOREDIV_TECHS_DUMP` AND
   `state.game_over` (so it never fires during normal play, matching `SCOREDIV_HAPPY_DUMP`'s own
   existing `state.game_over` gate immediately above it in the same function). Purely a read; returns
   the exact same `stats` value as before in all cases.

Neither hook is reachable unless the corresponding env var is explicitly set, so neither changes any
program behavior when unset (the normal/production/test/guard-check case). Verified this claim
directly: with both hooks compiled in but unset, `replaystats`'s completed-ID set over the full 1011-
game corpus is BYTE-IDENTICAL to the same run with the hooks reverted (`git stash`/`git stash pop`
A/B, see VERIFICATION below) -- 310/310 completed, 281/310 exact matches, both exactly matching the
documented baseline.

No functional fix is landed for any of the five games, so no new `#[cfg(test)] mod` test was added
(the task's "every fix gets a test, confirmed RED" rule applies to fixes; there is no fix here to
test). `cargo clippy --all-targets -- -D warnings` passes clean (no wildcard match arms introduced --
both hooks are simple `for`/`if` loops over existing iterators). `cargo test --profile difftest --lib`
passes 1359/1359, unchanged from baseline.
