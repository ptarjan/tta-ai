STEP 4/5 -- trace and root cause
========================================================================
Traced game 7523029 first (REPLAY_DEBUG=1 on a single-game tsv). The
rejected move was `Aggression { card: Plunder (II), target: 1 }`, phase
already correctly Politics (aggression IS a political action per
RULES_SPEC 5.1/CoL p.4 -- that part of the engine is fine), MA and hand
both present. legal.rs's own Aggression branch was the culprit:

    if combat::defense_strength(state, p, q) >= combat::attack_strength(state, p, q) {
        continue;   // never offer the move as legal
    }

This mirrors CoL p.4's printed declare-time rule verbatim: "You cannot
attack a player whose strength equals or exceeds yours" (confirmed by
reading sources/cge_code_of_laws.pdf directly, "Play an Aggression"
section). But it is FLATLY CONTRADICTED by BGO's own journals. Added a
temporary AGGR_STRENGTH_DEBUG eprintln at that exact call site and traced
all 9 of the other reachable Plunder-bucket games (the 10th, 7523471, isn't
actually Plunder -- see the corrected split above; 9 Plunder games besides
7523029 were traced with debug on):

    7523466 line 485: Purple plays Plunder against Grey

        attacker=1 defender=0 attack_strength=23 defense_strength=25  (attacker weaker)
    7523074 line 226: Orange plays Plunder against Purple

In every one of the 9, the defender's own "X defends ..." journal line
shows ZERO bonus/discard cards played -- so these ARE the pre-declaration
numbers, not a post-defense swing. 9 for 9, a human declared an Aggression
BGO itself computed as un-winnable (tied or worse) at declare time, and
BGO let them.

ROOT CAUSE (one sentence): legal.rs's pre-declaration `defense_strength >=
attack_strength` gate enforces CoL p.4's printed "cannot attack an
equal-or-stronger rival" rule, but BGO's digital implementation does not
enforce that half of the rule at all -- it only enforces the OTHER half
(FAQ "ties during Wars and Aggressions" / CoL "if your rival matches or
exceeds your strength, the aggression is unsuccessful"), which is a
resolution-time no-op already correctly implemented downstream by
combat::finish_aggression's own `if ctx.dfn >= ctx.atk { return false; }`.
The declare-time gate is both redundant with that and too strict.

FIX: removed the gate from legal.rs's CardType::Aggression branch (a
hopeless aggression is now offered as a legal move -- it still spends the
card and the MA, and still resolves to nothing on defense, matching BGO
exactly). Renamed and rewrote the test that encoded the old assumption
(`politics_aggression_not_generated_when_attacker_cannot_win` ->
`politics_aggression_generated_even_when_attacker_cannot_win`), documenting
the corpus evidence inline. Confirmed RED: temporarily re-inserted the old
gate, reran the renamed test, watched it fail
("assertion failed: moves.as_slice().contains(&Move::Aggression ...")"),
then restored the fix and reran -- GREEN (3/3 aggression-legality tests
pass). Full `cargo test --profile fasttest --lib` still 1418/1418, clippy
clean.

Not touched: War's own branch has no analogous strength gate (correctly --
declaring a War doesn't require the declarer to already be stronger, it
resolves next turn per RULES_SPEC 5.7/5.8), so this fix is scoped to
Aggression only, as it should be.
