===========================================================================
THE BUG: h_revolution never applied a pact's science discount
===========================================================================
Root cause, found by instrumenting every non-test writer of `PlayerState::science`
(apply.rs, combat.rs, economy.rs, events.rs, interact.rs) with a debug print gated
behind the existing `debugflags::replay_debug_all()` flag, then replaying game
7523162 alone with REPLAY_DEBUG_ALL=1 and reading off the trace around Grey's
round-9 revolution.

`apply.rs::h_revolution` (violent §8.3.4 Revolution, `Move::Revolution`) computed
its science charge as a bare, undiscounted `Card::revolution_cost` lookup:

    fn revolution_cost(id: CardId) -> i32 {
        id.get().revolution_cost as i32
    }
    fn h_revolution(state: &mut GameState, idx: u8, id: CardId, ...) {
        let cost = revolution_cost(id);
        ...
        p.science = p.science.saturating_sub(cost.max(0) as u16);

completely unlike the PEACEFUL path (`h_develop` -> `costs::tech_cost`), which
correctly reads `effects::state_stats(state, p).tech_discount` -- the pact-derived
science discount (e.g. Scientific Cooperation's "pays 2 science less") -- and
subtracts it before charging. `costs.rs`'s own doc comment on `tech_cost` even
says outright: "Both science discounts... apply to EVERY technology,
unconditionally... governments very much included" -- but that promise was kept
only for the PEACEFUL government-change price (`peaceful_cost`), never for the
VIOLENT one (`revolution_cost`), a second, entirely separate cost number for the
same government that Paul has ruled must stay independently representable
(costs.rs's own comment on why `tech_cost` and `revolution_cost` are not derived
from each other).

CONFIRMED against real human play, game 7523162, journal line 265-292:
  line 265: Orange proposes Scientific Cooperation to Grey ("Every time one of
    the civilizations plays a technology, it pays 2 science less and the other
    civilization pays 1 science").
  line 266: Grey accepts.
  line 292: "Grey revolutions Change government to Constitutional Monarchy;
    4 science points spent; Orange loses 1 science; Grey loses 4 science;
    Grey scores 3 culture"

Constitutional Monarchy's printed revolutionCost is 6 (verified against
sources/bga_throughtheages_material.inc.php's own `techcostbon` field, and matches
`card_table.rs`'s baked `revolution_cost: 6` -- the CARD DATA is correct). The
journal's own "4 science points spent" is exactly 6 - 2 (the pact's discount).
Our engine, missing the discount entirely, charged the FULL 6 -- a real, silent
2-science OVERcharge, with the drop landing exactly at the `Move::Revolution` that
caused it (journal line 292), not at some unrelated later point.

(A residual note on the original bug report's framing: the earlier PACTS worker's
note described the drop as appearing mysteriously between journal lines 296 and
301 with "no journal event that should touch Grey's science" in between. That
specific window claim does not hold up under direct instrumentation -- the drop is
visible already AT line 292, before their own line-296 checkpoint, and their "6 at
line 296, confirmed correct" claim was apparently a hand-arithmetic slip that
happened to plug in the CORRECT discounted revolution cost (4) as an input, not a
verification of what their own code actually computed at that point. The
underlying overcharge is real either way; only the earlier note's exact
reproduction window was slightly off.)

Two call sites needed the same fix, not just the charge itself, or the legality
gate and the charge would disagree:
  - `apply.rs::h_revolution` -- the actual charge.
  - `legal.rs::can_revolt` -- the "can I afford this revolution" legality gate,
    which also compared `p.science` against the bare printed cost. Left alone,
    this would have gone on REJECTING a real, human-legal revolution (enough
    science for the discounted cost but not the printed one) as illegal.
  - `legal.rs`'s `DevelopTechnology` move-generation arm (the Breakthrough
    "may spend its order on a revolution instead" branch, RB p.15) had the exact
    same bare-cost bug in a second, independent copy of the same comparison.

===========================================================================
THE FIX
===========================================================================
New shared helper, `costs::revolution_cost(state, p, id) -> Option<i32>`
(costs.rs, next to `tech_cost_net`): reads the printed `Card::revolution_cost`,
returns `None` for the "not printed" sentinel (Despotism, only government with
none) BEFORE the discount is applied (so a discount can never fully zero out a
real cost and get confused with "no revolution cost"), then subtracts
`effects::state_stats(state, p).tech_discount` and floors at zero -- exactly
mirroring `tech_cost`'s own treatment of the same discount pool.

Callers updated to use it:
  - `apply.rs::h_revolution` (the charge) -- the old private `revolution_cost(id)`
    helper is deleted, fully superseded.
  - `legal.rs::can_revolt` (the legality gate).
  - `legal.rs`'s `DevelopTechnology` move-generation arm's Breakthrough-revolution
    branch (the second bare-cost copy).

5 new tests, RED-confirmed by reverting the fix (`costs::revolution_cost` back to
a bare `Card::revolution_cost` read, `h_revolution`/`can_revolt` back to their old
comparisons) and re-running -- all 5 failed, all pass again after re-applying:
  - costs.rs: `revolution_cost_applies_the_pact_science_discount` (the exact
    7523162 numbers: printed 6, pact discount 2, expect 4)
  - costs.rs: `revolution_cost_stays_none_for_despotism_even_under_a_pact_discount`
    (sentinel-vs-floor-to-zero distinction)
  - costs.rs: `revolution_cost_floors_at_zero_when_the_discount_exceeds_the_printed_cost`
  - apply.rs: `h_revolution_applies_a_standing_pact_science_discount_to_its_own_cost`
  - legal.rs: `can_revolt_true_under_a_pact_discount_that_a_bare_printed_cost_would_reject`

Lib tests: 1438 passed (1433 baseline + 5 new), fasttest profile, ~13s.
Clippy (`cargo clippy --all-targets -- -D warnings`): clean.

FINAL ANSWER TO THE ORIGINAL QUESTION
===========================================================================
"What code path removes the two science points from Grey between journal
lines 296 and 301 in game 7523162?"

Best-evidenced answer: no code path does, in that exact window -- the
premise of that specific window was slightly off (see the note earlier in
this file). The real, confirmed 2-science removal happens EARLIER, at
journal line 292 itself (Grey's own `Move::Revolution` to Constitutional
Monarchy), inside `apply.rs::h_revolution` (now `apply.rs`'s `h_revolution`
plus the new `costs::revolution_cost` helper it calls): it charged the full
printed `Card::revolution_cost` (6) with NO pact discount applied at all,
where BGO's own journal shows the true, pact-discounted cost is 4 -- a
silent, real 2-science OVERcharge to the revolutioner. This is now fixed
(costs.rs, apply.rs, legal.rs -- see above) and measures clean.

A SEPARATE, additional 1-science drift also affects Grey in the immediately
following lines (268 before the revolution, 301 after it) via the pact's
"other civilization pays 1 science" clause, previously entirely
unimplemented anywhere in the crate. That is also now fixed (effects.rs,
apply.rs, legal.rs -- see "SECOND HALF" above) and also measures clean.

Mutation sites checked and ELIMINATED as the cause (confirmed via a full
before/after debug trace of every non-test `PlayerState::science` writer in
apply.rs, combat.rs, economy.rs, events.rs, interact.rs, replayed against
game 7523162 alone with `REPLAY_DEBUG_ALL=1`): `on_take_card` (Aristotle),
