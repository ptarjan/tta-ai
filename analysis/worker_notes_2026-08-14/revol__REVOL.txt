=== STEP 4: trace to root cause ===

Representative game: 7522515 (Robespierre, cost/culture correct per
engine, so the SIMPLEST case in the "not a pact/cost issue" group).

Isolated with the header row, replayed with REPLAY_DEBUG=1. The
rejected move's own debug dump:

  DEBUG try_apply fail: mv=Revolution { card: Republic }
  actor(current)=1 civil_actions=1 military_actions=4
  government=Despotism leader=Maximilien Robespierre ...
  science=7 ...

science=7 >= Republic's revolution_cost=3, so `can_revolt`'s science
gate passes. The failure is `legal::revolt_pool_ok`'s Robespierre arm:
`p.military_actions == effects::state_stats(...).military_actions`.
Despotism (2 MA) + Robespierre (+1 MA) = 3, but the LIVE stored pool
was 4 -- one too many.

Traced with an instrumented `h_play_leader`/`antiquate`: at journal
line 209 ("Purple elects Maximillien Robespierre"), the engine's OWN
state already believed Purple's leader slot was EMPTY
(`old_is_none=true`), even though the journal shows Purple's actual
leader chain was Hammurabi -> Joan of Arc (line 88, "Hammurabi dies")
-> Robespierre (line 209) with NO leader-death event for Joan of Arc
in between. Joan of Arc (Age I, +1 MA) had in fact been correctly
antiquated by `game::antiquate` at the Age II->III transition
(RULES_SPEC line 244 / CoL p.3, RB p.21: "an Age I leader dies when
Age II ends" -- confirmed CORRECT behaviour, matches the real BGO
game, Purple genuinely has no leader at that point in the real game
too).

The bug: `game::antiquate`'s own PRIVATE, DUPLICATED copy of
`on_leave_play` (duplicated from apply.rs rather than shared, per its
own pre-existing doc comment, because apply.rs's version is private)
stopped at blue/yellow-token bookkeeping -- it never gave back the
antiquating leader's flat `civil_actions`/`military_actions` bonus,
unlike apply.rs's `on_leave_play`, which already does this for a
leader REPLACED mid-turn (and is itself already tested for it:
`replacing_a_leader_with_a_flat_military_action_bonus_mid_turn_does_
not_claw_back_actions_already_spent_from_it`). So when Joan of Arc
antiquated, her +1 MA survived as a permanent ghost in Purple's LIVE
per-turn pool (2+1=3 stayed 3, should have dropped to 2). Then when
Robespierre was elected into the now-empty slot, `apply::
on_enter_play`'s empty-slot branch does a bare `p.military_actions +=
1` (assumes nothing to net against an empty slot), landing on 3(ghost)
+1(Robespierre) = 4 -- exactly the observed, wrong value. A fresh
`effects::state_stats` recompute correctly says 3 (no ghost), so
`revolt_pool_ok` sees 4 != 3 and rejects every revolution for the rest
of the game.

RULES CITATION: RULES_SPEC.md line 244 ("Death at age end: a leader is
removed from play when it becomes ANTIQUATED ... [CoL p.3, RB p.21]");
apply.rs's own `on_leave_play` doc comment ("a leader carrying a flat
civil_actions/military_actions bonus ... leaving play mid-turn ...
must give back the headroom it added") already establishes this is a
general rule for ANY leave-play, not just replacement -- antiquation
is a leave-play with no rules basis for exemption.

=== STEP 5: the fix ===

1. `game.rs::on_leave_play` (the antiquation-only duplicate) now also
   subtracts `eff.civil_actions`/`eff.military_actions` from the live
   pool, clamped at 0 -- mirrors apply.rs's on_leave_play exactly.

2. `game.rs::antiquate`'s leader-removal block now ALSO wraps the
   whole leave-play with `apply::carry_over_action_pool` (made
   `pub(crate)`, was private), snapshotting old/new totals and
   already-spent amounts exactly like `apply::h_play_leader` already
   does for a mid-turn REPLACEMENT. This matters because a flat
   subtract alone would claw back actions the player had already
   spent from OTHER sources this same turn whenever the antiquating
   leader's own bonus is smaller than what's left of it -- the
   IDENTICAL failure mode `h_play_leader`'s own doc comment already
   traces and fixes for leader replacement (game 7522520). Without
   this second half, the pool-only fix from (1) alone still left one
   guard regression (7521974) that (2) then fixed too.

Both are `#[cfg(test)]` covered: `game.rs::tests::on_leave_play_gives_
back_a_military_action_when_a_leader_antiquates`, confirmed RED by
temporarily reverting the `on_leave_play` CA/MA lines and re-running
just this test (it failed: `military_actions` stayed 3 instead of the
expected 2) -- then re-applied and confirmed GREEN again.
