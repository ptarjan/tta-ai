FIXES LANDED (file/function -> rule -> citation)
-------------------------------------------------
Fix 1 -- rust/src/apply.rs `take_card` / new
`take_card_from_international_agreement`; call site
rust/src/interact.rs `ChoiceKind::TakeRow` handler (~line 546).
Split `take_card` into a shared `take_card_impl(..., record_taken_this_turn)`.
The normal `h_take` path still records taken_this_turn (so an ordinary
Take still blocks same-turn play, RB p.14/CoL p.6). The International
Agreement TakeRow path now does NOT record it, per `docs/RULES_SPEC.md`
line ~383 (RESOLVED, CoL p.12): "if the current player takes cards,
action cards taken may be used the same turn."

Fix 2 -- rust/src/replay_common.rs, `ActionClass::PlayActionCard`
handler, right before `r.try_apply(Move::PlayAction { card }, true)`.
When `kind == FreeActionKind::IncreasePopulation` (Frugality), mirrors
the EXISTING synthesis already present in the ordinary
`ActionClass::IncreasePopulation` arm (same file, a few hundred lines
above): if the journal's own "spends N food; spends M resource" total
equals `economy::pop_cost`, and the shortfall is covered by a live
Trade Routes Agreement side-B grant (`economy::
trade_resource_as_food_remaining`, RULES_SPEC.md 5.9), synthesize the
missing `Move::TradeResourceAsFood` calls before applying PlayAction.
This is a REPLAYER fix (reconstructing an elided intermediate move),
not an engine legality change -- explicitly permitted by the existing
sibling code path it mirrors, and consistent with "fix the engine, not
the replayer's tolerance" because it does not skip/coerce/forgive
anything: it makes the SAME two real moves the human made, in the SAME
order, rather than one move the engine never offered.

Fix 3 -- rust/src/legal.rs, new `breakthrough_robespierre_ma_fundable`
(near `revolt_pool_ok`); rust/src/apply.rs `h_play_action` (payment
branch) and `h_revolution` (the `via_ordered_action` adjustment); new
`PlayerState::breakthrough_ma_funded` field (rust/src/state.rs) reset
in `economy::end_of_turn`. RB p.15 frames Breakthrough's own "1 CA" as
specifically funding the revolution ("Breakthrough may pay for the
revolution with its 1 CA + revolution science cost"), not as an
order-independent card-play fee. Maximilien Robespierre's own exception
(CoL p.12: "pay with all military actions instead of civil") therefore
reaches that cost too, when civil is already exhausted and a revolution
is genuinely one of Breakthrough's live ordered-action outcomes right
now (gated via `free_action_moves(..., DevelopTechnology, ...)`
containing a `Move::Revolution`). The `h_revolution` `via_ordered_action
&& robespierre` correction (an EXISTING, already-landed fix from a
prior pass, comment cites 9/10 BGO journals) assumed Breakthrough's 1
CA always came out of civil; when it was paid via military instead
(this fix), that correction must NOT also fire, or it credits a civil
action never spent -- the new `breakthrough_ma_funded` flag is exactly
that signal, consumed once by `h_revolution` and reset at end of turn
as a backstop if the order ever resolves to a plain Develop instead
(untested in the corpus but theoretically reachable).
Confirmed against 4 real BGO games: 7522616, 7523206, 7523163, 7522793
(all: take Robespierre, take a government card, elect Robespierre,
revolt via Breakthrough, all same turn, civil hits 0 before the
revolution line).

Fix 4 -- rust/src/legal.rs `bach_moves` (added a `discount: i32` param,
threaded through the cost formula) and its NEW second call site inside
`free_action_moves`'s `BuildOrUpgradeUrbanBuilding |
UpgradeFarmMineOrUrbanBuilding` arm; rust/src/apply.rs `h_bach_theater`
(added `discount`/`free` params) and a new `Move::BachTheater` arm in
`apply_free_civil_move`'s dispatch (previously unreachable -- the
function's own doc comment enumerated the producible Move shapes and
BachTheater was not among them). RB p.24: "Once per turn, as a civil
action, you may upgrade one of your urban buildings to a theater of the
same or higher level, paying the resource cost difference as normal."
This is a single once-per-turn privilege (`p.bach_upgrade_used`,
unchanged gate) that BGO lets a player fund EITHER bare (1 CA, full
cost) OR via a yellow action card's discount ("using Efficient
Upgrade"/"using Urban Growth") -- confirmed by BGO printing the SAME
leader-name-as-actor convention for both ("Johannes Sebastian Bach
upgrades X to Y[ using Z]"). Confirmed against 5+ real BGO games:
7521377, 7521798, 7523221, 7521653, 7523392 (directly, in the
IllegalMove:PlayAction bucket) plus 7522066, 7522674, 7522973, 7523545
(same mechanism, different bucket -- ParserGap -- before the fix).
