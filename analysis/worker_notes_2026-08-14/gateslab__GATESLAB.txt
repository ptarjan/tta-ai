    FALSIFIED. `level()` is a direct `age as u8` read (A=0..IV=4), matches

    `ResourcesPerLabEqualToLevel` arm and `output_modifier_value`'s twin both
    filter on `id.kind() == CardType::Lab` with no additional exclusion.

(c) Counting per WORKER when the rule is per CARD, or vice versa.
    FALSIFIED (formula is per-worker, and per-worker IS correct). Cross-
    checked two ways:
      - RULES_SPEC's own unresolved-question log (line 347) cites
        faq_v15.pdf's worked example for the IDENTICAL mechanic on the OTHER
        lab-bonus leader, Sid Meier (`CulturePerLabEqualToLevel`, same

        production, 1 worker * level 3) + 4 (Bill Gates: level 2 * 2
        workers) = 7 -- and BGO's OWN journal line states production of
        EXACTLY "7 resources" for that turn. The engine's Bill-Gates
        arithmetic reproduces BGO's own stated number exactly. This is
        airtight: whatever is wrong, it is not this formula.

(d) The yield applied to a stats recompute but not the actual banked
    resource, or applied once per turn when it should be per production

    FALSIFIED for THIS mechanism (the +4 for Bill Gates DOES reach `p.resources`

Engine charges 2 CORRUPTION resources that BGO's own journal does not show:

TWO OTHER lines in this exact journal file (round 7 and round 9, both Green)
DO show "CORRUPTION! Green loses 2 resources" when the engine agrees corr=2

is BGO's own consistent convention in this file, so its absence here is
strong evidence real corruption was 0 for Purple this turn, not merely an
unlogged formatting quirk.

`blue_total`, `blue_used` sanity-checked by hand against the live debug
output and found INTERNALLY CONSISTENT with the engine's own model:
  - blue_total=17 = base 16 (RULES_SPEC 1.2/6.2, "16 blue in blue bank") + 1
    from Purple's "Developed Territory (I)" colony (`effects.blue_tokens: 1`
    in card_table.rs, correctly applied by `interact::gain_colony`).
  - blue_used=7 = `tokens_for(9, food_denoms=[3,1])` (3, exact) +
    `tokens_for(8, mine_denoms=[3,1])` (4, with 2 remainder units) = 7. This
    is the PROVABLE MINIMUM token count representable for these totals given
    the currently-owned card denominations -- no real (rules-legal, "never
    move tokens up") placement history can use FEWER tokens than this. So
    the engine's blue_available=10 (hence corr=2, matching RULES_SPEC's
    16-11=0/10-6=2/5-1=4/0=6 bands, also verified byte-correct) is
    mathematically the BEST CASE the current scalar-repack model can ever
    produce for these totals -- and it STILL disagrees with BGO's implied
    truth (blue_available >= 11). I could not identify a further scalar
    input (blue_total, p.resources, p.food) that is simply wrong by hand;
    every one I checked (Coal, Bronze, Scientific Method's own worker count,
    Democracy's/Bill Gates'/Library of Alexandria's/Developed Territory's
    own `blue_tokens` effect fields) matched the data files exactly.

I take this as decisive evidence that the true defect is NOT a wrong scalar
input, but the MODEL ITSELF: `blue_used` re-derives a "minimal token
packing" from the scalar totals fresh on every call
(`economy.rs::blue_used`, `tokens_for`), which is provably a LOWER BOUND on
any real, rules-legal placement history and therefore can never overshoot in
the direction that would explain BGO showing LESS corruption than this
lower bound already implies -- UNLESS the true blue-token capacity/occupancy
bookkeeping itself needs the full placement-history model (which card
specifically holds each token, tracked over time) rather than a scalar
re-derivation, which is EXACTLY the representation change
corrskip2__CORRSKIP2.txt / corrskip2.patch already built (a real
per-denomination `TokenBank` tracked in `PlayerState`, wired through every
gain/pay/production call site). I was not able to get that patch to apply
cleanly against this warm template (context conflicts with the template's
own already-present SCIDRIFT oracle diff, unrelated to corrskip2) within
budget, so I could NOT empirically confirm it fixes this exact repro -- see
"WHAT I DID NOT ESTABLISH".
