This is a general timing rule, not specific to this game: strength is
evaluated at RESOLUTION (start of the attacker's next turn), and anything
that changes the table state in the interim -- including a tactic the
DEFENDER plays on their own intervening turn -- counts. 2p turn order
(Purple round15 -> Orange round16 -> Purple's next turn) puts a full
Orange turn between declaration and resolution, exactly when Orange set
up Fortifications.

ENGINE TIMING WAS ALREADY CORRECT.
rust/src/combat.rs::resolve_war_outcome reads
`effects::state_stats(state, ...).strength` live, at the moment it's
called (start-of-attacker's-next-turn per apply.rs's own comment at line
1175). It does NOT snapshot at declaration. Verified by instrumenting it
with a temporary eprintln (removed before committing) and running just
game 7522009 through replaystats:
  DEBUGWAR round=16 attacker_idx=1 a=37 target_idx=0 d=26
attacker (Purple) = 37 exactly matches the journal's "Attacker's
strength: 37" -- only the defender side was wrong. That ruled out a
timing bug (a timing bug would also perturb which state fields is being
read, but here the ONLY discrepancy is a fixed 2-point gap on one side).

ROOT CAUSE: card_table.rs's baked Fortifications entry (Age II tactic,
composition = 2 artillery) had `effects.strength: 4` / `obsolete_strength:
2`. Cross-checked against sources/bga_throughtheages_material.inc.php
(the actual BGA game-data dump that produced this journal): Fortifications'
own `artybon`/`artybonplus` = 5/3, NOT 4/2. Every *other* Age II tactic in
card_table.rs bakes its PHP artybon/artybonplus pair verbatim:
  Conquistadors    PHP 5/3  engine 5/3  OK
  Defensive Army   PHP 6/3  engine 6/3  OK
  Mobile Artillery PHP 5/3  engine 5/3  OK
  Napoleonic Army  PHP 7/4  engine 7/4  OK
  Classic Army     PHP 8/4  engine 8/4  OK
  Fortifications   PHP 5/3  engine 4/2  MISMATCH (only one)
data/cards_military_actions.json (the repo's own source-of-truth JSON that
card_table.rs is baked from, checked by the existing test
`every_field_of_every_baked_card_matches_the_value_recomputed_from_data`)
had the SAME wrong 4/2 pair with a self-consistent but wrong description
("+4 strength per army (+2 if outdated)") -- so this was a transcription
error baked into the data file itself, not a divergence between the data
file and the generated table.

Orange's army at resolution: 2 Cannon (Age II artillery, exactly fresh for
a level-2 tactic) + 1 Air Forces (doubles one army's tactic bonus). With
the wrong 4/2: 1 fresh army * 4 = 4, doubled = +4, tactic contribution 8.
With the correct 5/3: 1 fresh army * 5 = 5, doubled = +5, tactic
contribution 10. Difference: exactly 2 -- matches the observed gap.

FIX (both kept in sync, per the existing baked-vs-data consistency test):
  data/cards_military_actions.json: Fortifications strength 4->5,
    obsoleteStrength 2->3, effects.tacticBonus 4->5,
    effects.tacticBonusObsolete 2->3, text description updated.
  rust/src/card_table.rs: Fortifications effects.strength 4->5,
    obsolete_strength 2->3.
