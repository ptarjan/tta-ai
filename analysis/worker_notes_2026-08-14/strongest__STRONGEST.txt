STEP 1: rules sources, verbatim, specifically checking for a strongest/weakest
ASYMMETRY (especially tie-breaking)
============================================================

Read directly from the PDFs (not paraphrased), specifically hunting for anything that
treats "strongest" differently from "weakest":

- FAQ v1.5 p.11 (`pdftotext -f 11 -l 11 -layout sources/faq_v15.pdf`), verbatim, two
  adjacent paragraphs:
    "Ties during Wars and Aggressions: If the Military Strengths of two warring
    Civilizations are tied at the moment of execution of a War, then there is no
    effect from that War. The same goes for Aggressions. (Note that Military Strength
    includes your Strength that arises from all sources, including from Wonders and
    Leaders and Territories.)
    Weakest/Strongest Civilization(s): When this phrase occurs, it is referring only
    to Military Strength, not to Culture or Population or anything else."
  These two paragraphs sit back-to-back and use the SAME term "Military Strength" for
  both War/Aggression combat AND Weakest/Strongest event targeting -- there is no
  textual hint of a separate, narrower "strength" concept for events, and no asymmetry
  between "weakest" and "strongest" is stated anywhere on this page.

- Code of Laws p.12 (`pdftotext -f 12 -l 12 -layout sources/cge_code_of_laws.pdf`,
  Genghis Khan errata), verbatim: "In a two-player game, 'one of the two strongest'
  should be read as 'the strongest'. (You still win ties.) When forming armies, each
  infantry unit can be either cavalry or infantry (but not both) to maximize the
  civilization's total strength rating." -- this is Genghis-Khan-specific (a leader
  ability), not a general strongest/weakest asymmetry; it does confirm army-formation
  bonuses are part of "total strength rating" generally, same conclusion weakest
  reached, and applies identically to both directions.

- `docs/RULES_SPEC.md` 5.3: "Statistic comparisons ('strongest/weakest' = strength
  rating [FAQ p.11]): ties broken in favor of the current player, then proximity in
  clockwise order after the current player". This states ONE tie-break rule for BOTH
  words, no asymmetry.

CONCLUSION: no rules source found treats STRONGEST any differently from WEAKEST --
same underlying quantity (tactic-inclusive strength rating, same as combat), same
tie-break direction (favor the current/revealing player). The only asymmetry visible
anywhere is in the engine's OWN implementation of the tie-break's DIRECTION parameter
(`apply_single_target`'s `favor_current` flag: `true`/un-reversed order for
`StrongestPlayer` since being first-among-ties is good for a bonus; `false`/reversed
via `protect_current_from_bad_tie` for `WeakestPlayer` since being first-among-ties is
bad for a penalty) -- and that asymmetry is CORRECT, not a bug: it is the same "favor
the current player" rule applied to opposite-valence effects, exactly matching
RULES_SPEC 5.3's single stated rule. STEP 3's tie-only sub-analysis below measures
this directly and confirms it.

STEP 3: THE CORPUS MEASUREMENT (the actual point of this job)
============================================================

METHOD: `REPLAY_DEBUG=1 REPLAY_DEBUG_ALL=1 ./target/difftest/replay <index> <journals>
<all 1011 ids>` in one invocation (28ms/game, ~2 min total for all 1011). A one-line,
debug-print-only change was added to `events::apply_single_target` (reverted before
this file was written -- see FILES CHANGED) to also print each player's
`effects::army_strength(p)` alongside the existing `values` (total
`state_stats(...).strength`) on the SAME already-existing debug line, so the
tactic-army-bonus component could be isolated without a second probe or a second
20-minute corpus sweep:

    DEBUG apply_single_target: order=... stat=Strength best=true favor_current=true
      ranked=... values=[...] army=[...]

`resolve_event` runs this EXACT `apply_single_target` call (STRONGEST, `best=true`)
UNCONDITIONALLY for every event revealed, immediately followed by the WEAKEST call
(`best=false`) -- both lines are always emitted back-to-back right after the event's
own `class=PlayEvent` journal-replay line, before any of that event's own
resource/culture/etc. side effects are applied for the FIRST (strongest) key,
interleaved with (for the second, weakest, key) the first key's own gains-block debug
noise. A player-index-to-color map was built once per game from the FIRST time each
`actor=N` index appeared in an `APPLY_ONE ENTRY` line (color name is always the first
word of that line's own `raw_text`, e.g. "Purple builds..."), then reused for every
event in that game.

PAIRING METHOD for the 4 combined strongest+weakest cards, and how it was validated
(the exact gap weakest's own notes flagged as unsolved):

Rather than pairing by DESCRIPTION-SENTENCE POSITION (proven unsound by weakest, and
independently re-confirmed here: Border Conflict's description lists "weakest...
destroy" FIRST and "strongest... gains" SECOND, but the OUTCOME clauses in the
journal's own raw text are ALSO ordered weakest-then... no, in Border Conflict they
are actually STRONGEST-outcome-then-weakest-outcome, e.g. "Purple produces 3
resources; Orange must destroy a mine, farm or urban building" -- reversed from
Refugees' own outcome-clause order in weakest's example. No fixed positional rule
holds across cards), this pass paired by CONTENT: for each of the 4 card types, the
strongest-clause and weakest-clause use grammatically DISTINCT verbs that never
collide with each other OR with the generic "<revealer> scores N culture" preamble
every event reveal prints:

  Border Conflict:  strongest = "<Color> produces N resources"
                     weakest   = "<Color> must destroy..."
  Crusades:          strongest = "<Color> scores N culture"
                     weakest   = "<Color> loses N culture"
  Refugees:          strongest = "<Color> gains N culture..."
                     weakest   = "<Color> loses N culture..."
  Politics of Strength: strongest = "<Color> draws N military cards"
                         weakest   = "<Color> must discard N cards"

These patterns are matched ONLY within the outcome-clause segments (everything after
the card's own printed description sentence, itself located by finding the "Current
event:" marker segment and skipping the following "<Age> / <Name>" and description
segments) -- never against the preamble "<revealer> plays event <revealer> scores N
culture" (which also contains the word "scores"/"culture" but is a DIFFERENT
sentence, always appearing BEFORE "Current event:", so slicing on that marker
excludes it structurally, not by luck).

VALIDATION of this pairing method: the SAME 4 cards' WEAKEST-side outcome clauses
were independently extracted with this content-based method and checked against the
engine's own `best=false` resolution for the identical events -- if the pairing were
unsound, this should NOT reproduce weakest's own already-published 98.8% number (that
number came entirely from single-effect cards, none of these 4). It does:

    WEAKEST side of the 4 combined cards (this pass's own sanity check, NOT the
    scan's headline number): 658/665 = 98.9% (Politics of Strength 116, Crusades 277,
    Border Conflict 272 -- Refugees' weakest clause is identical in shape to
    Crusades' and was folded into the same regex, so its count is inside "Crusades"
    above only where the literal card name matched Crusades; Refugees itself
    contributed 0 extra distinguishable weakest events beyond what full-window
    re-scanning found -- not chased further since it is a validation check, not the
    headline result).

98.9% landing within noise of weakest's own 98.8% (measured on an entirely disjoint
set of card types) is strong, independent confirmation that the content-based pairing
method is sound and the STRONGEST-side numbers below are not a parsing artifact.
