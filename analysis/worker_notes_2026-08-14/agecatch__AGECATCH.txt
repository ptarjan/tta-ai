THE PREDICATE ACTUALLY IMPLEMENTED
====================================
Per the previous worker's own "WHAT'S NEEDED" note (scorediv__SCOREDIV.txt,
end of DEEP-DIVE 1): trust a `PlayEvent` line's own age tag for
`catch_up_civil_age` ONLY when BOTH:

  1. the line's own actor (via `corpus::actor_and_rest`, then
     `Color::seat()`) equals `state.current` at the moment the line is
     reached in the replay loop, AND
  2. `state.pending`/`state.queue` are both empty.

Implemented at `replay_common.rs`'s single `catch_up_civil_age` call site
(~line 5521-5523 at 628c0dd, inside `replay_game`'s main loop), leaving
`is_trustworthy_age_line` itself (and its OTHER call site,
`last_real_decision_line_for_age`, the backward check) completely
untouched -- i.e. this predicate is intentionally scoped narrower than
even the task description's phrasing suggests: it does NOT change
`is_trustworthy_age_line`'s answer for `PlayEvent` in general (still
`false`, matching every other confirmation class), it only adds a SEPARATE
OR-condition at the one call site that actually needs the exception:

    let outcome = classify(card_index, line.text);
    let is_current_actors_own_play_event =
        matches!(&outcome, LineOutcome::Action(Classified { class: ActionClass::PlayEvent, .. }))
            && actor_and_rest(line.text).is_some_and(|(actor, _)| actor.seat() == r.state.current);
    if is_trustworthy_age_line(outcome) || is_current_actors_own_play_event {
        catch_up_civil_age(&mut r.state, line.age);
    }

Condition 2 (pending/queue empty) is NOT re-implemented here -- it is
already `catch_up_civil_age`'s own unconditional internal guard (line
5236: `if state.pending.is_empty() && state.queue.is_empty() { ... }`), so
adding it again at the call site would be redundant; the OR-condition only
needed to add condition 1.

This is deliberately narrower than blanket-trusting `PlayEvent`
(`is_trustworthy_age_line`'s own doc explicitly documents the class as
"BGO logs the confirmation BEFORE the real action that causes it" --
generally untrustworthy) and deliberately does NOT touch
`last_real_decision_line_for_age` (the "hidden twin" backward check,
`is_trustworthy_age_line`'s own doc insists both call sites get an
IDENTICAL answer to avoid a silently-diverging exception list) -- because
that function is a static one-time prescan over the whole journal BEFORE
any replay happens, with no `GameState` and therefore no notion of
`state.current` at a given line index at all. There is no way to express
"actor == state.current" there without actually replaying, so extending
the SAME predicate to both sites, as the doc's own invariant asks for, is
not mechanically possible for this specific carve-out. This is flagged
here as a real, unresolved tension with that doc's stated design, not
silently ignored -- but since the whole predicate turned out not to work
anyway, it was moot in the end.

A pinning test was written, verified RED (temporarily reverting just the
new OR-condition back to pre-fix `if is_trustworthy_age_line(outcome)`,
which made the test's second assertion fail with
`left: III, right: IV`), then GREEN again, then REMOVED along with the
production change when the full sweep regressed -- consistent with this
task's own "fix the engine, not the comparison" framing: a test pinning
behaviour that regresses the corpus is not a fix worth keeping.


WHY IT REGRESSES 7523021, TRACED
===================================
Game `7523021`'s journal, lines 233-241 (already Age III per the journal's
own age column since line 217 -- no II->III transition is visible in this
window):

  235  Orange  III 15  Orange discovers Justice System ...

  240  Orange  III 15  End turn Orange scores: ...
  241  Orange  III 15  Orange discards 1 card    <-- StuckPending fires here

Line 234 ("Orange plays event ... Iconoclasm") is a `PlayEvent` line whose
own actor (Orange) IS `state.current` at that point in the replay: Purple's
turn had just fully closed at line 233 ("No Discard Phase", a Bookkeeping
trailer with nothing outstanding), so the turn had already legitimately
passed to Orange before line 234 is even reached. `state.pending`/
`state.queue` are both empty too (nothing is mid-resolution). This means
BOTH of the new predicate's conditions are satisfied -- it is
indistinguishable, for this exact line, from the blanket "trust every
PlayEvent line" version the previous worker already tried and reverted.
Forcing the age catch-up here (rather than deferring it to whatever line
first triggers it under the OLD rule) is what desyncs some later
hand-limit/antiquation timing enough that by line 241 `decider() !=
expected_actor()` with nothing pending -- the identical `StuckPending:
decider # != expected actor #, phase Actions, no pending` failure, at the
identical line, confirmed by isolating just this one game
(`/tmp/one_ac.tsv`, single-game `replaystats` run) and reading its own
Stop-reason histogram entry directly:

  | 1 | 15.0 | StuckPending: decider # != expected actor #, phase Actions,
    no pending | 7523021 line 241: Orange discards 1 card |

So the "acting player is `state.current`" half of the specified predicate
does not actually discriminate between 7523021's bad case and 7523162's
good case: both are the CURRENT player's own live `PlayEvent` line, with
nothing pending. Whatever the real difference between the two games is
(if any exists that keeps this safe), it is not "was this a same-timestamp
collision with a different player's still-open turn" -- 7523021's line 234
is not that shape at all; Purple's turn had genuinely, fully closed one
line earlier. The regression is therefore NOT the "hidden twin" collision
hazard `is_trustworthy_age_line`'s doc warns about (that hazard is about
BGO's EXPORT ordering being unreliable across players at the same
timestamp); it is a plain "forcing this specific age-catch-up strictly
earlier than the old, deferred point changes downstream turn-timing state
in a way this reconstruction's hand-limit/antiquation logic depends on,
for reasons not further traced here" -- out of scope to chase per this
task's own "if the predicate does not work, say so and stop" instruction.
