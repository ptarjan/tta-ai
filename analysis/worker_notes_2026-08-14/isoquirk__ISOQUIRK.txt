WHAT WAS CLAIMED
----------------
A previous worker reported that game 7522315 "cannot be isolated for
single-game measurement -- a replaystats tooling quirk worth fixing", and
that this blocked their investigation.

WHAT ACTUALLY HAPPENS
---------------------
Build a one-row index (header + the game's row) and run it:

    head -1 sources/bgo/index.tsv > /tmp/iso_one.tsv
    awk -F'\t' '$1=="7522315"' sources/bgo/index.tsv >> /tmp/iso_one.tsv
    SCOREDIV_DUMP_COMPLETED=1 ./target/difftest/replaystats \
        /tmp/iso_one.tsv /private/tmp/bgo-journals/journals > /tmp/iso_one.txt 2>&1

That works. It emits a complete report for the one game: 262 decisions
recorded, 36 discard checkpoints, 36 culture checkpoints, and every oracle
section populated.

The one line that appears in BOTH runs is byte-identical:

    - 7522315 line 130 (round 8 age II, Purple): journal's cross-validated
      excess 0, this binary computes 1 (hand_military_len 3 limit 2)

Full sweep: 1011 sampled, 671 completed, 630 exact -- the current baseline,
unchanged. One-row run: 1 sampled, 0 completed, stop reason
`IllegalMove: Build` at line 346.

THE REAL EXPLANATION -- one example per bucket, not one row per game
--------------------------------------------------------------------
`grep 7522315 /tmp/iso_full.txt` over the FULL sweep returns exactly ONE
line, from the discard-phase oracle. The game's culture divergence and its
stop reason do not appear anywhere in the full-sweep output.

That is not data loss. Every other section of the report is a HISTOGRAM: it
prints a count per bucket and ONE example game for the bucket. 7522315 is
counted in its culture bucket (`BuildWonderStage`) and in its stop-reason
bucket (`IllegalMove: Build`), but some other game is the one named as the
example. Isolating the game to one row makes it the only candidate, so it
becomes the example everywhere and all its detail appears.

So the tool behaves correctly and identically in both modes. What misled the
earlier worker is that grepping the full sweep for a game ID is NOT a way to
see that game's findings -- the histograms deliberately name one example
each. Isolating to a one-row index is exactly the right move, and it works.

HOW TO ISOLATE A GAME (this is the supported workflow, use it freely)
---------------------------------------------------------------------
    cd <clone>/rust
    PATH=$HOME/.cargo/bin:$PATH cargo build --profile difftest --bin replaystats
    head -1 /Users/pt/tta-ai/sources/bgo/index.tsv > /tmp/one.tsv
    awk -F'\t' '$1=="<GAME_ID>"' /Users/pt/tta-ai/sources/bgo/index.tsv >> /tmp/one.tsv
    ./target/difftest/replaystats /tmp/one.tsv /private/tmp/bgo-journals/journals \
        > /tmp/one.txt 2>&1

The header row is required -- the parser skips line 1. Never pipe
replaystats through `head`; SIGPIPE truncates or kills the run.
