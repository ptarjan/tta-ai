=== ROOT CAUSE ===

For 15 of the 38 games, the wonder (or another card whose absence later
starved the player of civil actions/resources) was granted via the
"International Agreement" event (Code of Laws p.12: "The strongest
civilization may immediately take up to 5 civil actions in cards..."),
NOT via a normal "<Color> takes <Card> in hand <Color> uses N civil
action" row-take line. BGO logs this event's picks as:

    International Agreement <Color> takes <Card> in hand[; <Color> takes
    <Card> in hand]*

i.e. the event's own card name leads the line (no leading player colour),
and multiple picks are packed onto ONE journal line, semicolon-joined,
with NO "uses N civil action" cost clause on any of them (they're paid
from the event's own 5-CA-equivalent budget, not the player's civil-action
pool -- interact.rs's ChoiceKind::TakeRow handler bills `budget`, not
`p.civil_actions`).

`corpus::classify()` had a late catch-all: "if a known card name leads the
line, it's Bookkeeping" (built for trailing consequence lines like "Impact
of X ..." and "Bill Gates scoring ..."). Since "International Agreement"
is itself a card name (the event card), this catch-all silently swallowed
the ENTIRE take line -- the card never entered `p.hand_civil`, and for a
wonder specifically, `p.wonder` was never set at all (`apply::take_card`
only sets it when the card is actually taken). Confirmed directly: 3 of
the 38 games (7522543 Kremlin, 7521981 First Space Flight, 7522807
Hollywood) failed with the engine's own debug print
"wonder_stage_cost(...)=-1 wonder=none" -- i.e. the engine had NO wonder
in progress at all when the human's journal showed them building a stage
of one. The other 12 International-Agreement games in the bucket failed
via a plain affordability shortfall a turn or more later (the dropped
card was a tech/action card whose absence meant less CA/resources than
the human actually had).

This is the same general shape flagged in the task brief ("a leader whose
effect BGO never prints a journal line for") but inverted: here BGO DOES
print the line, but our classifier discarded it anyway.


=== THE FIX (3 parts, all in rust/src/) ===

1. corpus.rs `classify()`: added a case, checked BEFORE the generic
   card-name-prefix Bookkeeping catch-all (same reason Christopher
   Columbus's case sits just above it), recognizing
   "International Agreement <Color> takes <Card> in hand" as
   `ActionClass::TakeCard` for the FIRST pick. "<Color> declines
   international agreement" and a bare "International Agreement" line
   fall through unchanged to the existing catch-all (still Bookkeeping --
   a genuine silent decline, matching this file's established "no journal
   trace for a decline" precedent).

2. replay_common.rs: a new no-leading-colour special case in the main
   per-line loop (mirrors the existing Barbarossa/Alexander/Columbus
   blocks), triggered when `class == ActionClass::TakeCard &&
   line.text.starts_with("International Agreement ")`. It:
   - resolves the actor from column 2 (`Line::color`), confirmed reliable
     against every sampled example;
   - walks the line's own remaining ";"-joined "<Color> takes <Card> in
     hand" clauses to collect ALL picks on this one line (classify() only
     ever resolves the first);
   - re-resolves every pick through `best_age_sibling` (this was itself a
     second bug hiding behind the first: cards with multiple age copies,
     e.g. "Reserves", need the age-correct CardId or nothing downstream
     matches -- this alone caused 2 of the fix's own regressions before
     being added, see below);
   - calls `resolve_intervening` ONCE (for the first pick only -- it
     drains the QueueItem::TakeRow the event enqueued; every later pick's
     own re-offer is already synchronous inside interact.rs's own
     ChoiceKind::TakeRow handling, so calling it again per pick was a
     second bug: with the pick not yet grounded anywhere, its own
     matches_upcoming always read false and auto-declined the just-
     reopened choice via Stop);
   - grounds each pick against the OPEN TakeRow choice's own offered
     `Slot` options (preferring an already-grounded identity match, else
     the first ungrounded offered slot) rather than `ground_row_slot`'s
     generic cost-matching (International Agreement picks carry no
     "uses N civil action" clause to match a slot's normal take_cost
     against -- feeding the observed-cost default of 0 into
     `ground_row_slot` was a third bug: it demanded a slot whose ORDINARY
     position price is exactly 0, true for at most one row slot).

3. replay_common.rs `resolve_intervening`'s own pre-existing TakeRow
   `matches_upcoming` check (used by the SAME file to decide whether to
   auto-drain a stale TakeRow via Stop) required the taken card to
   ALREADY be present in `card_row` by CardId identity. That's true for
   nothing the row has never held before -- exactly a wonder taken via
   International Agreement, which never appeared in the row under any
   earlier "takes"/"builds" line. Extended the check to also match an
   UNGROUNDED offered slot (trusting the journal's own stated take the
   same forgiving way `ground_row_slot`'s "first ungrounded slot" branch
   already does everywhere else in this file). This was found AFTER the
   first regression-bar pass: two guard games (7522957 "Reserves",
   7523114 "First Space Flight") regressed because this pre-existing gap
   silently closed the TakeRow choice via Stop before my own new code
   ever got a turn -- see the "false starts" section below.

=== FALSE STARTS WORTH KNOWING ABOUT (for anyone touching this area again) ===

- First attempt routed each International Agreement pick through
  `apply_one`'s existing generic `ActionClass::TakeCard` arm. That arm's
  `ground_row_slot(actor, card, Some(observed_take_cost(raw_text)))` call
  assumes every take line carries a real "uses N civil action" cost
  clause; International Agreement's picks never do, so
  `observed_take_cost` silently defaulted to 0, which then demanded a row
  slot whose ORDINARY position price is exactly 0 -- wrong almost every
  time. Symptom: "ParserGap: open TakeRow choice does not offer slot #",
  14/1,011 games. Fixed by NOT routing through that arm at all for this
  shape; ground against the open TakeRow choice's own offered Slot
  options instead (part 2 above).
- Second attempt called `resolve_intervening` once PER PICK (not once per
  line). Since a pick isn't grounded until AFTER resolve_intervening
  returns, its own `matches_upcoming` check always read false for pick
  #2+, auto-declining the just-reopened TakeRow via Stop before it could
  be used. Symptom: "ParserGap: International Agreement pick with no open
  TakeRow choice", 36-42/1,011 games. Fixed by calling
  `resolve_intervening` exactly once, for the first pick only.
- Third: `best_age_sibling` needed to be applied to every pick's resolved
  CardId, not just left as whatever `corpus::build_card_index` happened to
  return (an arbitrary same-name sibling for the 9 card families BGO
  never age-tags in text). Missing this caused the two genuine
  regressions (7522957 "Reserves", 7523114 "First Space Flight" -- the
  latter has no age siblings at all, so this alone wasn't its full fix,
  see next point).
- Fourth (the deepest one, part 3 above): even with the age-sibling and
  per-line-not-per-pick fixes, 7523114 (First Space Flight, a wonder with
  no age siblings) still regressed, because `resolve_intervening`'s
  OWN pre-existing TakeRow `matches_upcoming` logic requires the picked
  card to already sit somewhere in `card_row` by identity -- structurally
  impossible for a card never seen in the row before. This is a real,
  pre-existing gap in `resolve_intervening` that was simply never
  exercised before this fix (nothing used to classify these lines as
  TakeCard at all, so this code path was dead for this shape). Fixed by
  widening the match to also accept an ungrounded offered slot.

Looked briefly at three of the remaining games:
- 7521364 has 8 "GAME DATA UPDATED <Player> <Resource>: A -> B" lines --
  an admin correction BGO occasionally injects, currently classified as
  pure Bookkeeping (corpus.rs, the literal-string check right next to
  "Attacker's strength:"/"Operation successful"). These corrections
  genuinely change a player's resource count, but nothing applies them --
  the resource delta is simply dropped. This is a real, distinct gap
  (only 2/27 remaining games have any GAME DATA UPDATED lines at all, so
  it is NOT the dominant remaining cause, just worth flagging since it's
  an easy grep away: `grep -c "GAME DATA UPDATED" journals/*.tsv`).
- 7521849 shows persistent per-turn "science drift" (engine computes
  science several points lower than the journal's own running total,
  every single turn, well before the WonderStep refusal) -- looks like an
  unrelated, pre-existing tracking bug (possibly Leonardo da Vinci's
  leader ability, "gives 1 resource" on a discover, not fully tracked)
  that starves the player of resources by the time they try to build.
  Did not chase this further -- it's a different bucket's shape (a
  silent-resource-gain leader ability, the exact pattern flagged in the
  task brief for a DIFFERENT bucket already root-caused).
- The remaining ~24 games were NOT individually triaged beyond confirming
  none of them carry an International-Agreement take line before their
  own WonderStep refusal (i.e. they are not instances of the same root
  cause) and are a mix of small (1-2 resource) and larger affordability
  shortfalls per `costs::wonder_stage_cost` vs `p.resources` at the point
  of refusal -- most likely several more small distinct causes (production
  tracking drift of the same general shape as 7521849, or something
  wonder-cost-specific not yet identified). A fresh pass should group
  these by which OTHER action class most recently preceded the refusal
  (Reserves/Engineering Genius plays, tech discoveries, etc.) the same way
  this pass grouped by International Agreement.
