PART 1: THE DISCARDSOLVER ROBUSTNESS FIX (the actual task)
============================================================================

THE MECHANISM (in my own words)
--------------------------------
`discard_solver::DiscardSolver` resolves a forced military-hand discard by
constraint propagation: `prescan_future_military_needs` scans the WHOLE
journal up front for every later `"plays <military card>"` line and records
a `FutureNeed { lineno, card }`. At any discard decision, `needed_after`
returns every `FutureNeed.card` still in the player's future, and `choose`
rules out any currently-offered candidate whose EXACT `CardId` appears in
that set -- a candidate that reappears in a later named play, by
construction, cannot be the one just discarded.

The bug: `FutureNeed.card` is not a fact, it is a GUESS.
`corpus::build_card_index`'s bare-name lookup for a same-name-recurring
family (Plunder/Raid/Territories/etc.) picks ONE age-sibling arbitrarily
(whichever iterates first when the index is built) -- BGO's journal text
never carries an age tag. `prescan_future_military_needs` uses that raw,
uncorrected guess. Elsewhere in the replayer, OTHER code (`TakeCard`'s
`best_age_sibling`, and now `PlayAggression`'s own Plunder correction, see
Part 2) narrows that same guess to a DIFFERENT, more accurate `CardId` at
the moment the card is actually consumed.

Before this fix, `needed_after`/`choose` compared EXACT `CardId`s. So the
identity `DiscardSolver` protects at every EARLIER discard decision was
whatever the prescan's uncorrected guess was -- and the identity that later
actually gets consumed (once corrected) is a DIFFERENT `CardId`. Since every
candidate offered at a discard decision is itself SIMULATED filler with no
journal-verified identity of its own (this module's own doc comment), the
only thing that ever made an exact-`CardId` comparison "work" was that BOTH
sides (the future need's guess and the discard candidate's simulated
identity) happened, by construction, to be built from the same uncorrected
guessing procedure. Correcting ONE side (fixing `PlayAggression` to resolve
the right age) without correcting the OTHER (the discard candidates'
simulated composition, an emergent property of many turns of `ground_for_
consumption`/`repay_military_hand_deficit` pop-then-push calls) broke that
accidental agreement -- an EARLIER, textually unrelated discard decision's
"is this candidate needed later" answer could flip, purely because the
exact `CardId` a future need now pointed at moved.

This is confirmed by the plunder worker's own experiment: making the
prescan's guess and `PlayAggression`'s resolution use the EXACT SAME
age-bound formula (`age_civil` in one attempt, `age_military` in another --
literally identical values on every line) still produced the IDENTICAL 21
regressions either way. If the bound itself were the problem, the two
bounds should have diverged on at least some lines; they didn't, because the
real problem was never "which bound" -- it was that ANY change to the
resolved identity, however it's computed, can flip an unrelated earlier
discard purely through this exact-identity coincidence.

THE FIX
-------
`discard_solver.rs`, `DiscardSolver::needed_after` and `DiscardSolver::
choose`: match by card FAMILY (`Card::base_name`) instead of exact `CardId`.
`needed_after` now returns `HashSet<&'static str>` (family names) instead of
`HashSet<CardId>`. Five call sites in `replay_common.rs` (`ground_for_
consumption`, `ground_bid_ceiling`, `ground_auction_winner_hand`,
`repay_military_hand_deficit`, and `resolve_political_decision`'s
`PrepareEvent` deficit path) updated from `.contains(id)` to
`.contains(id.get().base_name)` to match.

This makes protection INVARIANT to which exact age-sibling a future need's
guess resolves to, in either direction -- correcting `PlayAggression`'s
Plunder resolution (or any future correction to any other `consume_named_
military_card` call site) can no longer move the protected set, because the
family a future need belongs to never changes, only which of its siblings
gets guessed.

This is strictly MORE conservative than exact matching (a superset of what
it used to protect), never less: it can turn a `Solved` discard into a
`Chosen` or `ForcedCollision` one in the rare case a player's simulated hand
holds two different-age siblings of the same family at once (both get
protected even though only one is truly needed), but it can never let a
genuinely-needed family through unprotected, and `choose` always still picks
SOME legal candidate either way -- it never blocks progress.

FIRST ATTEMPT REJECTED: age-bound guessing is ITSELF unreliable
-------------------------------------------------------------------

(`best_age_sibling(card, r.state.age_military)`) in `PlayAggression`,
Plunder-scoped, reproduced the EXACT SAME 8 regressions the plunder worker
already found for that scope (`7521906 7521914 7522054 7522107 7522526
7523015 7523404 7523486`) -- DESPITE Part 1's robustness fix already being
in place. Traced `7521906` (line 138, `StuckPending("PlunderSplit choice
open for player 1 but no journal-observed Plunder resolution left to
resolve it with")`): the journal's own line 135 reads "...up to 3 resource
and/or food..." -- Age I -- but `best_age_sibling(card, r.state.age_
military)` picked Age II, because `age_military` had already advanced to II
by the time this particular Plunder was finally played (the card was drawn
at Age I and sat in hand unplayed through an age transition). The bound
"highest age not exceeding the current one" is a GUESS that overshoots
exactly as easily as `build_card_index`'s arbitrary pick undershoots -- it
is not a fix for the underlying problem, just a differently-shaped guess.
This is NOT a DiscardSolver-coupling regression at all; it is a plain wrong
answer from the resolution logic itself, and no amount of DiscardSolver
robustness could paper over it.

THE ACTUAL FIX: read the journal's own printed number, don't guess a bound
-------------------------------------------------------------------------
Plunder prints a different "up to N resource and/or food" per age (3/5/7
for I/II/III, `TakeFromOpponentBlock.food_and_or_resources` in
`card_table.rs`) on EVERY "plays Plunder" line, with no other occurrence of
that phrase on the line to collide with (confirmed corpus-wide). This pins
the exact age down with NO guessing in either direction -- strictly
stronger evidence than any bound, the same "read the observed effect, don't
guess" principle `resolve_named_card_by_effect` already uses for Build/
Upgrade/Develop.

`replay_common.rs`:
  - `trailing_up_to_resource_and_or_food(text) -> Option<i32>`: parses the
    "up to N" clause.
  - `plunder_food_and_or_resources(id: CardId) -> Option<i16>`: reads a
    card's own `TakeFromOpponentBlock.food_and_or_resources` (`if let`, not
    a `match` with a wildcard arm -- `Special` has ~80 variants and the
    project's clippy gate denies `_ =>` over an enum).
  - `resolve_plunder_age(card: CardId, raw_text: &str) -> CardId`: no-op for
    every non-Plunder card; for Plunder, parses the text and matches it
    against `family_siblings(card)`'s own printed value; falls back to the
    original (arbitrary) `card` if nothing parses or matches -- never worse
    than the pre-correction guess.
  - `ActionClass::PlayAggression`'s arm now reads
    `let card = resolve_plunder_age(card, raw_text);` right after resolving
    `card` from the journal text.

Scoped to Plunder only (matching the plunder worker's own final scope
decision) -- Raid/Enslave/Spy/Annex/Infiltrate share the same age-blind
resolution shape in principle (decider__DECIDER.txt independently found the
identical bug on Raid, game `7523354` line ~212) but were not verified
against their own card data this session. See PICKUP PLAN.
