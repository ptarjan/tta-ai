WHY THE VIOLATIONS ARE IN THE OLD FILES AND NOT THE NEW ONES
----------------------------------------------------------------
The gate mechanism has been correct at both load time
(load_weights -> dominance_repair, eval.rs:1099) and mutation time
(mutate -> dominance_repair, climb.rs:401) since the SIGNAUDIT
structural fix. What 8576d25 changed is the PERSISTED value: the
champion JSON now stores the repaired vector, not the raw post-mutation
one. So:
  * Any champion file written BEFORE 2026-08-25 10:33 can carry a
    gate violation in a block-arm key (or any gated key) -- the repair
    ran in memory during the climb but the on-disk file was the raw
    vector. The preclimb/postclimb frozen copies are exactly such
    files.
  * Any champion file written AFTER that timestamp is repaired by
    construction. The live and clamp_ceiling files all postdate it
    (clamp_ceiling frozen 2026-08-27 07:24; live gens 118815/66395/
    21660 are well past the fix), and they show zero violations.
  * This is consistent with the SIGNAUDIT finding that the gates were
    "very nearly decorative" before the write fix: the climb could
    walk a penalty weight positive (or a credit negative) in memory,
    repair it for the next mutation, and still persist the illegal
    value. The repair was doing its job in the run; the file just
    didn't reflect it.
