THROUGH THE AGES -- CANDIDATE-SET SPREAD QUANTILES (2026-08-24)
================================================================================
MEASUREMENT ONLY. No redesign, no clamp change landed. Produced to check
whether analysis/clamp_design_2026-08-24.txt's `bound(k) = 70.0 / mean_spread(k)`
formula is the right one, per this task's brief: a MEAN-based bound hands the
LOOSEST bound to a feature that varies on 1% of decisions but swings huge when
it does -- backwards, since the clamp exists to stop exactly that feature from
drifting to enormous magnitude and dominating the rare decision where it fires.

================================================================================
METHOD
================================================================================
Matches analysis/feature_audit_2026-08-24.txt's own methodology exactly, so
this file's `mean_spread` column is directly comparable to that file's (values
differ slightly because the live champion files move every few minutes under
the running climb; both files freeze a champion snapshot at the moment of
their own run, per this task's instructions -- see LIMITATIONS below).

At every real self-play decision point (`filter_resign`d legal-move count > 1)
reached by WeightedBot::choose under a given player count's LIVE CHAMPION
weights, every legal move is applied to a scratch clone and
eval::candidate_features() is read for each resulting state (candidate_features
IS linear_features run once per candidate, pinned by eval.rs's own
linear_features_dotted_with_a_weight_vector_reproduces_evaluate_exactly test).
Per WeightKey, per decision: spread = max(candidate values) - min(candidate
values). The move actually walked is chosen separately by WeightedBot::choose
on the same state (not re-derived from the candidate_features scores), so
self-play visits the same decisions the champion actually reaches.

TOOLING: no existing rust/src/bin/ tool computes candidate-set spread (the
feature_audit's own featspread.rs was written and run inside ITS OWN isolated
clone, which was cleaned up after that audit finished, per the standing
"isolated clone, never touch the live tree" convention -- it never landed in
the tracked repo). Rewrote a new rust/src/bin/featspread.rs inside THIS task's
own isolated clone (/private/tmp/spreadwork, deleted at the end of this run),
reusing eval::candidate_features and WeightedBot::choose exactly as the prior
audit did, and extending its aggregation with:
  fire_rate                = fraction of decisions where spread > 1e-9
  mean_spread_when_firing  = mean spread over ONLY the firing decisions
  p95_spread                = 95th percentile (nearest-rank) of spread over
                               firing decisions
  max_spread                = maximum spread observed
alongside the original mean_spread (over ALL decisions, firing or not), so the
two tables stay comparable.

COMMAND RUN (from rust/, in the isolated clone):
  cargo build --profile difftest --bin featspread
  ./target/difftest/featspread \
      --weights-2p ../experiments/rust_champion_2p.json \
      --weights-3p ../experiments/rust_champion_3p.json \
      --weights-4p ../experiments/rust_champion_4p.json \
      --games 40 --seed 0 --threads 2 --out featspread_quantiles.txt

Champion files: cp'd into the isolated clone BEFORE this ran (the live
/Users/pt/tta-ai/experiments/rust_champion_*.json are rewritten by the running
climb every few minutes; this measurement never reads them directly).

SAMPLE SIZE: 40 self-play games per player count (120 games total), producing
10,101 (2p) + 15,562 (3p) + 25,155 (4p) = 50,818 real decision points (>1 legal
move post-filter_resign), each with its full legal-move candidate set scored.
Chosen deliberately smaller than the original audit's 200 games/count
(253,906 decisions) -- this task asked for "at least a few thousand decisions
per player count" for p95 to be meaningful, --threads 2 (not 6) to avoid
starving the three climb arms running on this machine, and this task's own
tool-call/time budget. 50,818 decisions comfortably clears "a few thousand" at
every player count, with headroom (10x+) even at 2p, the smallest count.
