  With gain=0 and armies=0, `tactic_value` always falls into its third

  `(reach_credit * (potential*strength_m - cost)).max(0.0)`. Since

ANSWERS
-------

(1) Is every Tactic card's price exactly 0.0 at 2p and 4p?

    NO. The original suspicion is REFUTED. Every Tactic card prices
    strongly POSITIVE at 2p (14.26 to 185.42) and even more strongly at 4p
    (60 to 780), scaling linearly with the card's printed
    `effects.strength`. This is NOT the dedicated `tactic_value` path (that
    branch never fires at 2p/4p -- tactic_board_credit is 0.0 there) -- it
    is the SAME generic "both credits zero" fallback every other
    credit-gated card type (tech/gov/action/wonder/aggression/war/pact/
    event) already has: `card_yields(id)` + `sum_yields(..., CardRateCredit)`.
    `card_yields` (cards.rs ~305-315) explicitly, and deliberately, pushes a
    Tactic's own top-level `effects.strength` as a flat `WeightKey::Strength`
    Gain yield when it is not a Unit card, with a comment already stating
    this is the intended fallback for `tactic_board_credit == 0.0`.

    Instead, the actual blackout is at 3p, where tactic_board_credit IS
    nonzero (0.0415) -- see answer (2).

(2) What is the spread of Tactic prices at 3p?

    EXACTLY 0.0 for all 15 cards, no spread at all -- the true blackout.
    Mechanism: at 3p tactic_board_credit != 0.0, so `card_potential_core`
    takes the dedicated `tc * tactic_value(...)` branch and `return`s its
    result directly, WITHOUT ever falling back to the flat `card_yields`
    price 2p/4p get. In the sampled 3p board state `tactic_value` itself
    legitimately returns 0.0 for every card (see diagnostic above:
    `tactic_reach_credit` dominance-clamped to 0.0 combined with a board
    where no tactic composition is close to formable yet) -- so the "more
    sophisticated" board-aware pricing path is *strictly worse* than what a
    credit of exactly 0.0 would have given the same card at this exact
    board state. That is the real, confirmed defect: `tactic_board_credit`
    was gating the WHOLE term (flat fallback included) rather than just its
    own board-aware bonus.

(3) Aggression/War comparison at 2p (same "if credit != 0.0" shape) --
    is Tactic uniquely switched off, or is this a whole-family problem?

    Whole-family PATTERN, but Tactic is the odd one out for a different
    reason than assumed. At 2p, aggression_board_credit=0.1125 (on) and
    war_board_credit=0.3165 (on), so BOTH go through their dedicated
    `aggression_value`/`war_hand_value` functions, not the generic
    fallback -- and both give real, varied, sometimes-negative numbers
    (Aggression: 0.09, 0.00, 0.07, 0.15, 0.00, -0.25; War: -0.29, -0.06,
    -0.81), unlike Tactic's clean linear-in-strength numbers.

    The comparison that actually answers the question is the credit==0.0
    case: at 3p, aggression_board_credit=0 and war_board_credit=0 too, and
    their generic fallback IS mostly exactly 0.0 (Aggression: 0, 0, 240.0
    [Enslave -- has a flat non-strength printed effect], 0, 0, 0; War: 0, 0,
    0) -- because most Aggression/War cards carry no printed *economic*
    yield `card_yields` recognises (their payload is combat/plunder
    effects, not `effects.strength`/culture/science/etc.), so their
    fallback genuinely is close to the original "priced at 0.0" hypothesis.
    Tactic is different only because a Tactic's printed `effects.strength`
    happens to already be a `card_yields` entry, so ITS fallback is not
    blank. So: the "credit == 0.0 sometimes collapses to a near-zero
    fallback" issue is real and general (Aggression/War's fallback is
    genuinely weak for most cards), but that is a *pre-existing, accepted*
    design (`card_yields` documents this on purpose) and out of this task's
    scope. Tactic's specific, confirmed bug is the INVERSE: its dedicated
    ON-branch (3p) can be worse than its OFF-branch (2p/4p) fallback,
    because the ON-branch fully replaces the fallback instead of adding to
    it.


PHASE 2 -- FIX
--------------

File touched: rust/src/bots/weighted/cards.rs (only).
No new WeightKey. No epsilon floor on tactic_board_credit. No hardcoded
formula -- both terms are the exact same trained-marginal functions every
other pricing path in this file already uses (`card_yields`/`sum_yields`
for the flat term, `tactic_value` -- itself built entirely off
`yield_marginal`/`unit_type_reach_cost` -- for the bonus).

Shape chosen: mirror the generic fallback's own `base` + `credit_board`
split (cards.rs ~1988-1992: `base` is unconditional, `credit_board` scales
only the board-aware swap-diff on top). Concretely:

  - `card_potential_core` gained one new local, `tactic_bonus: f64`,
    initialized to 0.0 *before* the `if let Some(b) = board` block (so it
    is visible at the shared fallback tail below that block, which runs
    unconditionally).
  - The Tactic arm no longer `return`s. It now does:
        let tc = w.get(WeightKey::TacticBoardCredit);
        tactic_bonus = tc * tactic_value(id, st, ix, w);
    and falls through, same as every OTHER kind whose credit is 0.0
    already does.
  - The three exit points of the shared tail (the "both credits zero" early
    return, the swap-diff return, and the final `total`) each now add
    `+ tactic_bonus`. For every non-Tactic card `tactic_bonus` is always
    exactly 0.0 (only the Tactic arm ever sets it), so this is a byte-for-
    byte no-op for every other card type.

Net effect: a Tactic card's price is now
    (flat card_yields fallback, unconditional)
  + tactic_board_credit * tactic_value(...)   (board-aware bonus, additive)
instead of the old
    tactic_board_credit != 0.0 ? tactic_board_credit * tactic_value(...)
                                : (flat card_yields fallback)
which is exactly the "additive bonus, not a gate on the whole term"
shape the task asked for, and exactly parallel to how `base`/`credit_board`
already split in the generic fallback just below it.

Effect at 2p and 4p (tactic_board_credit == 0.0 there): BYTE-IDENTICAL to
before -- `tactic_bonus = 0.0 * tactic_value(...) = 0.0` regardless of what
`tactic_value` returns, confirmed by re-running the probe (see "AFTER"
table below, 2p/4p columns unchanged to the printed precision).

Effect at 3p (tactic_board_credit == 0.0415): every Tactic card now prices
above zero, using the SAME flat card_yields term 2p/4p already had (since
`tactic_value` itself was still 0.0 in this sampled state, the bonus added
0.0 on top -- so this run only demonstrates the fallback restoration, not
the bonus; the bonus is exercised separately by the added test, using a
state where `tactic_value` is forced to bottom out at 0.0 by construction
rather than by chance).
