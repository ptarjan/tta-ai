A NOTE ON READING "+/- 0.00"
kindmatch's paired interval has width exactly 0.00 whenever the per-deal win share has
zero variance across the 60 (2p) / 30 (4p) complete deals. That happens in two very
different situations, and the task brief only describes one of them:
 (a) TRUE SILENCING -- the weight change never alters a single decision anywhere, so
     the "variant" strategy is byte-for-byte behaviourally identical to the champion.
     Two identical strategies duelled against each other land EXACTLY on the null win
     rate (50.00% at 2p, 25.00% at 4p) every single deal -> zero variance -> +/-0.00.
     This is the case the task is asking us to find.
 (b) DETERMINISTIC DOMINANCE -- the change is so large that it flips the SAME decision
     the SAME way in literally every deal, so the win share is a constant far from the
     null (e.g. 0.00% or 1.67%) -- also zero variance, also prints +/-0.00, but this is
     the most extreme form of LIVE, not silenced.
We disambiguate by checking whether the printed win rate sits exactly on the null. Only
one key exhibited case (b): card_board_credit at 2p (0.00% win, +/-0.00) -- flagged
separately below, NOT counted as silenced.
As instructed: interval width is the only thing treated as a strength signal here; win
rate magnitude for the ordinary nonzero-width rows is noise and no strength claims are
drawn from it.

unit_strength_credit (silenced both counts):
  Lines ~520 and ~1044, inside `sum_yields()`:
    YieldKind::Unit => amt *= w.get(WeightKey::UnitStrengthCredit),
  then gated by `if wk != 0.0 && amt != 0.0 { total += wk * amt; }` where wk is the
  OTHER weight paired with that yield triple (WeightKey::Strength for Unit-kind
  triples, base weight `strength` = 12.58 in the 2p champion, so that gate is open).
  A doc comment at line ~504-514 notes "at most one YieldKind::Unit triple exists per
  card today" -- i.e. this is already a rare code path by construction, consistent
  with staying silent even at 5000x the champion value in a 120-game sample.

card_rate_credit (silenced 2p only):
  Lines ~1881 and ~2161: `let credit = w.get(WeightKey::CardRateCredit);` then passed
  as the `credit` argument into `sum_yields(..., credit)`, where it multiplies
  YieldKind::Rate triples (`YieldKind::Rate => amt *= credit`), and separately as a
  multiplier for wonder-outlook valuation (`discount * board * gains_only_board_sum`
  path uses `board`, a different weight, when board!=0; the credit path is the
  fallback `sum_yields(&buf, w, credit)` when board resolution doesn't apply).

pact_board_credit (silenced at 10x both counts; opens at 500x/4p only):

    else if kind == CardType::Pact {

  Single multiplication against `pact_value(...)`'s return (not a further internal

build_fresh_credit (silenced 4p only):
  Line ~1203, inside the staffing-plan valuation:
    let build_credit = w.get(WeightKey::BuildFreshCredit);
    if build_credit != 0.0 { ... b_net *= build_credit; if b_net > net { net = b_net; } }
  `b_net` is itself a sum of feature-marginal-weighted yields for the "build one fresh
  worker" plan; it only replaces `net` via `max()` if it exceeds the OTHER staffing
  plan's net, so a very large build_credit still needs b_net (pre-multiply) to already
  be in a competitive range to matter -- a two-factor gate similar in spirit to
  free_action_credit's board-credit x marginal chain.

tactic_reach_credit (silenced 4p only):
  Line ~1352:
    let strength_m = yield_marginal(WeightKey::Strength, state, idx, w, None);
    let reach_credit = w.get(WeightKey::TacticReachCredit);
    (reach_credit * (potential * strength_m - cost)).max(0.0)
  Multiplied against `(potential * strength_m - cost)`, then floored at 0 by `.max(0.0)`
  -- so if that inner term is typically <=0 in the sampled games (cost routinely meets
  or exceeds the strength-marginal value of closing the gap), the whole term floors to
  0 regardless of how large reach_credit gets, which would explain persistence at 500x.

READINGS -- what the climb provably cannot learn, and where
=====================================================================
1. pact_board_credit is silenced (unlearnable by gradient walk) at BOTH 2p and 4p at
   the magnitudes the climb actually explores (it is currently at 0.0017 / 0.0993,
   and even 10x-100x that range moves nothing). At 4p specifically it is the SAME kind
   of coordinate as free_action_credit -- live in principle but requires a value
   ~5000x the current champion's to matter, which a local hill-climb will never reach
   by continuous small steps. At 2p it stayed fully dead even at 5000x, so 2p pact
   pricing may simply not be exercised by these seeded games (CardType::Pact cards
   rare/absent in the drawn decks) rather than just under-scaled.
2. unit_strength_credit is silenced at BOTH player counts and stays dead even at
   5000x the champion value -- best explained by the code comment itself: at most one
   Unit-kind yield triple exists per card today, so this coordinate is rarely, perhaps
   almost never, exercised regardless of its weight. The climb cannot learn it not
   because of a multiplier chain but because the code path barely fires.
3. card_rate_credit is silenced at 2p only (live at 4p, width 5.74) -- a genuine
   player-count-dependent finding: the climb can learn this coordinate at 4p but not
   at 2p at all, even out to 5000x. Worth flagging to whoever owns 2p card-rate
   pricing, since the 2p climb has been running far longer (gen 107806 vs gen 19733)
   yet has never been able to move this weight.
4. build_fresh_credit and tactic_reach_credit are silenced at 4p only (both live at
   2p). Both stayed dead at 5000x, and both sit behind a floor/max gate against a
   competing valuation, which is a plausible mechanical reason a large credit can
   still produce zero effect: the multiplied term is clamped to non-negative or must
   beat a competing plan, so scaling the credit alone does not guarantee it becomes
   decision-relevant.
5. Net structural point for the coordinator: after free_action_credit, this is the
   SECOND confirmed instance of a `_credit` weight requiring roughly 5000x its current
   champion value before it can be learned (pact_board_credit @ 4p) -- plus four more
   keys that look outright dead within the sampled games rather than merely
   under-scaled. Roughly a quarter of the 19 `_credit` keys are unlearnable as
   currently coded/scaled at one or both player counts.
