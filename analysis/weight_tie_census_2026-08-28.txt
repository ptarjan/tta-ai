--- 2p card_board_credit / card_board_leader: (b) evaluation-time composite ---

The OLD mechanism (pre-commit 83d1c2e, which is the one the running 2p arm still
executes): cards.rs credit_board composed the leader's board multiplier as
  credit_board = base + board_credit_key(id)
with base = w[CardBoardCredit] and board_credit_key(Leader) = CardBoardLeader.
eval.rs dominance_repair carried a COMPOSITE gate (the `card_board_credit_keys()`
loop, deleted from source by 83d1c2e) that fired when
  CardBoardCredit + CardBoardLeader < -1e-12
and whose remedy was exactly
  CardBoardLeader := -CardBoardCredit
projecting the pair onto the sum == 0 line in EXACT f64. That is the
equal-and-opposite shape: both halves land at the same magnitude, opposite
signs, sum exactly 0.0 -- which is precisely what the live file shows (the 2p
champion's own value, carried through generations since the arm's binary last
rebuilt). The climb cannot move the two independently: any candidate with a
negative sum is repaired back onto the line, and any candidate with a positive
sum is free but the pair then carries no information the search needs, so the
pair parks on the line.

Classification (b), not (a): the DOMINATES const at eval.rs:811-814 contains
only (ResourceStock, BlueFree) and (WonderPotential, WonderPromise); the
card_board pair is not in it. The repair that ties them is the separate
composite loop, deleted from source at 83d1c2e but still present in the
release binary the 2p arm is running.

STATUS: the fix is in source (83d1c2e decoupled credit_board to an absolute
multiplier; 1ed6d38 pins it with RED-confirmed tests) but NOT live: the release
climb binary is from 2026-08-27 07:37, predating both commits. The tie will
persist on the 2p arm until the arm is rebuilt and the pair re-mutates off the
