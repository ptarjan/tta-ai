IMPORTANT SIDE FINDING: the grounding-order "recovery" mechanism WORKS CORRECTLY
============================================================================
I initially suspected a structural bug: `finish_game`'s embedded `events::evaluate_final_events`
call can fire while `state.current_events`/`future_events` still hold the FICTIONAL simulated
pile, when BGO's journal logs the true final "End turn" line (which triggers
`game::advance_turn`'s round-wrap -> `finish_game`) BEFORE its own "End of game" marker line (the
line `ground_final_events` reads to correct the pile) -- confirmed this ordering for 8/28
diverging games (7522822, 7522906, 7521790, 7521789, 7522768, 7522813, 7523149, 7523102) via:
  eog_lineno=$(grep -n "End of game" journal | tail -1 | cut -d: -f1)
  lastend_lineno=$(awk -F'\t' '$5 ~ /^End turn/ {print NR}' journal | tail -1)
  # "BEFORE(suspect)" when lastend > eog is false

BUT: rust/src/replay_common.rs's existing `if r.state.game_over { if !completed { ... } }` recovery
block (around line 5355-5410, see its own doc and the
`replay_game_completes_a_journal_whose_duplicated_end_turn_pair_is_logged_before_its_own_end_of_
game_marker` test) is SPECIFICALLY DESIGNED for exactly this case and, on direct trace of game
7522906 (added temporary eprintln! probes, now removed), DOES correctly: (1) undo the wrong
fictional-pile award via a direct `final_event_awards` diff-and-subtract, (2) ground the piles from
the journal's real "End of game" line, (3) re-run `evaluate_final_events` against the corrected
pile. Hand-verified game 7522906's arithmetic end to end: baseline(98) + Bill Gates(+9, applied
once, correctly, during the premature finish_game since it does not depend on the event pile) +
[undo wrong Industry/Agriculture/Competition award] + [redo correct Colonies/Happiness/Balance
award] reproduces the engine's actual output (138) exactly, and the ONLY remaining gap from the
true index value (140) is the SAME "Impact of Happiness" formula bug named above (engine's
Colonies/Happiness/Balance redo computes Happiness as 14 instead of the journal's 16 for that
seat) -- not a grounding-order defect. CONCLUSION: the grounding-order mechanism is not a live bug
and should NOT be touched; my initial hypothesis was wrong and is recorded here so nobody
re-investigates it.
