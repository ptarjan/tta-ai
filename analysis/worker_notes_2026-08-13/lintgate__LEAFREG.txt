Result (measured, this run): 6457 real decision points checked, walking
sources/bgo/index.tsv games in file order against /tmp/bgo-journals/journals

replay_common::replay_game(record_decisions: true), Weights::default() as w:
  2p: 3580 decisions   3p: 321 decisions   4p: 2556 decisions
  max |dot(w, linear_features(state,idx,ctx,w)) - evaluate(state,idx,w,ctx,None)|
    = 1.4210854715202004e-13  (float noise, not a real discrepancy)
Every single decision passed the < 1e-6 tolerance assert; none were dropped
or excluded for disagreeing. This is a genuine identity on real corpus
states, not merely on the `new_game` toy positions the pre-existing test
(`linear_features_dotted_with_a_weight_vector_reproduces_evaluate_exactly`,
same file) already covered.

The code already documents WHY the identity holds (eval.rs's own doc
comments on `linear_features`, quoted/paraphrased here, not re-derived):
`evaluate`'s `WeightKey::ALL` loop and its four `PHASE_KEYS` (three
collapsed to a `start*(1-L)+end*L` two-parameter blend, `StrengthRel` given
its own round-gated `horizon::combat_unreachable` blend) are mirrored
coordinate-for-coordinate by `linear_features`'s own `PHASE_KEYS` handling,
including the `combat_unreachable` gate on `StrengthRel` specifically
(`out[StrengthRel] *= late` only inside that gate, matching `evaluate`'s
`if/else`). The ten identity-aware coordinates (HandPotential,
WonderPotential, WonderPromise, HandMilPotential, TacticGain, TacticShort,
RivalHandPotential, RowUrgency, RowBargainForgone, RowLastCopy,
MyEventThreat) are bilinear in `w` in the true `evaluate`, so the identity
is only exact when `linear_features`'s `freeze` argument equals the `w`
being dotted -- true here (`Weights::default()` used for both). Ctx was
built once via `rivals::rival_context(state, idx, None, None)` and shared
between the `evaluate` and `linear_features` calls in the test (the same
sharing discipline `WeightedBot::choose`'s own doc comment requires).

HYPOTHESIS (not measured further this task): the 222/1011 = 22% completion
rate is a property of replay_common.rs's own reconstruction fidelity
(documented elsewhere in this repo, docs/REPLAY.md, as an ongoing, tracked
gap -- BGO journals don't log every fact the engine needs, e.g. discard
identities, and a replay stops the instant a human's logged action fails
`legal_moves()` against the reconstructed state). This task did not
investigate or attempt to raise that rate -- out of scope ("do not fix
evaluate()" extends in spirit to "do not go rewrite the replayer" for a
data-generation task). If more training data is wanted later, the lever is
replay_common.rs's own fidelity, not leafdump.rs.

HYPOTHESIS: outcome labels (`win`) do not special-case rules §5.11's
`forced_winner` (a resignation immediately naming a winner independent of
score) because GameResult does not expose the final GameState to check it --
see leafdump.rs's own doc comment. Not measured how many of the 222 used
games this could affect (would require re-deriving `state.forced_winner`,
out of scope for this pass); flagged rather than silently assumed correct.

Outcome/target columns, exactly as requested: `win` (1/0, this seat vs. every
seat that round, ties sharing the win, `game::winners`'s own tie-break
convention), `final_score` (raw final culture for this seat,
`game::scores`'s own per-seat array), `final_rank` (1-based competition
ranking off that same array) -- so a later fit can pick win/loss, raw score,
or rank as its regression target without re-deriving any of the three from
the others.

--------------------------------------------------------------------------
MEASURED, structurally, not just reviewed.

FINDING (important, reconciles this task's brief with the actual code): the
task brief says "Rivals' HAND CONTENTS ... are PRIVATE and must never be
read." That is TRUE for hand_military but FALSE, per the actual rulebook,
for hand_civil: docs/RULES_SPEC.md §2.6 "Cards taken are public knowledge
(open civil cards convention) [RB p.7]" and docs/CHAMPION_VS_HUMANS.md's own
line 22 ("so a rival's hand_civil is public") both predate this task and
already establish that a rival's CIVIL hand identity is legitimately public
-- everyone at the table watches you take a specific card off the face-up
row into your hand. `bots/weighted/cards.rs::rival_hand_potential` reads
`q.hand_civil` for exactly this reason (its own doc comment cites the same
rule) and is the ONLY place in bots/weighted/*.rs that reads a RIVAL's hand
identity of either kind -- grepped exhaustively (`grep -rn "hand_civil\|
hand_military" src/bots/weighted/*.rs`, ~90 hits, every non-test,
non-comment read of `hand_military` outside `replay_common.rs` uses
`state.players[idx as usize]` i.e. the ACTOR's OWN hand, never a rival's).
Deck order (civil_deck/military_deck) is read ONLY via `.len()` anywhere in
bots/weighted/*.rs -- never contents/order. leafdump.rs therefore needed no
privacy filter of its own: it calls the SAME `linear_features` a live bot
calls, unmodified.
