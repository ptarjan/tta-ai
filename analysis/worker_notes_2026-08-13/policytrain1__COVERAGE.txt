WHAT IT ASSERTS
---------------
1. Loads the three real base-game data files (data/cards_civil.json,
   data/cards_military_actions.json, data/cards_wonders_leaders.json) with
   `crate::fixtures::parse_json` -- the same dependency-free JSON reader
   `card_table.rs`'s own `baked_table_matches_source_data` test uses, and
   asserts `scope == "base-2015"` exactly as that test does (expansion is
   out of scope by standing decision). This is a genuine load of the real
   printed data, not the baked-in `CARDS` static (which only carries fields
   `gen_cards.py`/the struct already knew to capture, so it could not have
   revealed a key nobody modeled).

2. Collects every TOP-LEVEL key of each card's `effects` JSON object,
   paired with the card's name (114 distinct keys across 236 cards).

3. Forward direction: every one of those 114 keys must be either
   (a) listed in DELIBERATELY_UNPRICED, or
   (b) listed in a new local table, PRICED_ELSEWHERE (defined inside the
       test module), which names every key genuinely priced OUTSIDE
       card_yields's own flat dispatch -- a CardEffects scalar field
       card_yields reads directly, a Special variant a different function
       consumes (card_choice, board_yields::government_plans/board_extra),
       a ring-fenced action_value/yield_marginal reroute, or a leader-NAME
       rider off board_yields::rider_of (Genghis Khan / Winston Churchill /
       Hammurabi). A key in neither table fails the test, and the failure
       message names the key AND every card it appears on.

4. Reverse direction (the task's explicit ask, and a second reverse check
   added for the same reason): every DELIBERATELY_UNPRICED entry, and every
   PRICED_ELSEWHERE entry, must still print on some real card -- so neither
   table can rot with a stale/typo'd/renamed key. Also: the two tables must
   not share a key (one claiming "priced", the other "deliberately not" --
   both cannot be true).

WHAT THIS DOES AND DOES NOT CATCH -- read before trusting the green result
----------------------------------------------------------------------------
DOES catch: any key printed at the top level of a base-game card's
`effects` object that is neither in DELIBERATELY_UNPRICED nor in the new
PRICED_ELSEWHERE table. Since this test currently passes, that means: as of
this commit, every one of the 114 top-level effect keys the base game
prints is accounted for by one of the two tables.

Does NOT catch, and this is a real, deliberate limitation, not an oversight
papered over:

  (a) PRICED_ELSEWHERE is a HAND-AUDITED allowlist, built by reading
      card_yields/board_yields.rs/action_value source once (this session,
      2026-08-13) and citing which function prices each key. It is not
      independently, mechanically re-derived from the pricing code the way
      card_table.rs's `baked_table_matches_source_data` re-derives CARDS
      from JSON. A future refactor that silently stops reading a
      PRICED_ELSEWHERE-listed field (e.g. someone deletes the `push(out,
      WeightKey::HappyMargin, eff.happy ...)` line) will NOT be caught by
      this test -- the key stays in PRICED_ELSEWHERE, still prints on a real
      card, and the test stays green while the bot silently stops pricing
      `happy`. Closing that second-level gap would need a behavioural check
      (call card_yields on a real card and assert a specific WeightKey
      shows up) for all ~29 PRICED_ELSEWHERE entries individually, which is
      real, separate work (see OPEN ITEMS below) -- deliberately NOT
      attempted here to stay within budget, and because faking that check
      shallowly (e.g. "assert card_yields' output is non-empty") would be
      worse than not having it.

  (b) Scoped to the TOP LEVEL of each card's `effects` object only. It does
      NOT recurse into nested blocks: a pact's `A`/`B`/`bothPlayers`
      sub-keys (`foodProduction`, `technologyScienceDiscount`, ...), an
      event's `allPlayers`/`weakestPlayer`/... sub-keys, `takeFromOpponent`'s
      sub-keys, `buildDiscount`'s per-age sub-keys, etc. Those wrapper keys
      ARE in DELIBERATELY_UNPRICED bucket 6 ("addressing"), so the wrapper
      itself is accounted for -- but a key ADDED inside one of those blocks
      later would not be audited by this test at all. This is the same
      scope DELIBERATELY_UNPRICED itself has always had (it is keyed by
      top-level printed strings too), so this test's coverage matches the
      table's own stated scope exactly -- but it is real and worth naming.

  (c) Does not audit top-level card fields that are effects "in all but
      name" (`strength`/`civilActions`/`militaryActions`/
      `urbanBuildingLimit` printed OUTSIDE the `effects` object, on units
      and governments) -- `card_table.rs`'s own KNOWN_TOP_KEYS test already
      owns that vocabulary (structural fields, not printed effects), and
      DELIBERATELY_UNPRICED itself is not keyed by them either, so this is
      consistent scope, not a gap this test silently introduces.

  (d) "Priced" here means "some function in the weighted-bot module reads
      this value and turns it into a WeightKey contribution", not "prices
      it correctly" or "prices it well". Existing pricing bugs on an
      already-PRICED_ELSEWHERE key are out of scope.
