VERDICT
-------
Zeroing ca_left DOES cut the expensive (cost-3) take share sharply -- from
48.5% down to 29.7% of all takes, a real and large effect in the direction
the hypothesis predicted. But that is not evidence the negative weight was
"buying the price": removing it does not make the bot take the SAME cards
more patiently. Instead the bot's civil-action spending collapses almost
across the board -- total takes per player-game drop 25% (17.58 -> 13.12),
"other" (non-Take) CA spending drops too (29.0% -> 21.3% share), and nearly
half of all civil actions now go completely unspent (20.3% -> 49.4%). The
negative ca_left weight is not narrowly a "row-take price bonus"; at the
strength trained (-5.44), it is the dominant force making the evaluator
prefer DOING SOMETHING over ending the turn at all. Strip it and the bot
becomes passive, not patient.

Consistent with this, forcing ca_left to its default +0.05 (arm C) makes
things WORSE in the same direction, not better -- more waste (51.0%), fewer
takes (12.99/player-game), lowest cost-3 share (26.2%). Waste and cost-3
share move together, monotonically, across all three ca_left settings
(-5.44 -> 0.0 -> +0.05: waste 20.3% -> 49.4% -> 51.0%; cost-3 share 48.5% ->
29.7% -> 26.2%). There is no free lunch in this one-weight cut: the
expensive-take share and the unspent-CA rate are the same lever, moving in
opposite directions together, not two independent bugs.

Both arm B and arm C lose head-to-head to the trained champion (arm A) at
p<0.001 over 200 games (38.2% and 37.0% win rate respectively, vs a 50%
null). Zeroing ca_left is a clear NET REGRESSION on actual game outcome,
despite improving the specific take-cost-distribution number the original
hypothesis cared about. This is a clean negative result for the hypothesis
as an actionable fix: the -5.44 ca_left weight is doing real, positive work
for the champion's win rate, not merely an artifact that inflates expensive
takes for no benefit. If cost-3 takes are still considered a problem, this
single-weight zeroing is not a viable fix -- it trades a take-cost cosmetic
improvement for a much larger, measured loss in games won.

METHOD NOTES
------------
- actioncensus.rs measures metric 1 (unspent-CA share) and the per-player-turn
  taking/other/unspent means used to derive metric 3's CA-spent numbers.
- behavcensus.rs's "Take cost" section measures metric 2 (1/2/3-CA take-cost
  distribution) and reports takes/player-game directly.
- arena.rs is the existing A/B duel binary; used directly for metric 4, no new
  code needed.
- No source files were modified in the final state (the one temporary unit
  test added to probe dominance_repair's output was reverted before any
  build/run below it). No commits were made; nothing needed changing in
  rust/src for this experiment since actioncensus, behavcensus, and arena
  already existed in this clone and needed no Cargo.toml registration
  (src/bin/*.rs auto-discovery).
- All commands run from /private/tmp/caleft/rust with
  PATH="$HOME/.cargo/bin:$PATH", --profile difftest only, never --release.
- /Users/pt/tta-ai was never touched; no git command was ever run there.
