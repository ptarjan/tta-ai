--------------------------------------------------------------------------
THE BUG, restated briefly (full trace already in GAMEDROP.txt, not
re-derived here)
--------------------------------------------------------------------------
68/789 skipped journals log BGO's duplicated trailing "End turn" line pair
BEFORE their own real "End of game" marker instead of after (100% of this
one bucket, 0 exceptions, confirmed across all 1011 journals). The FIRST
copy of that duplicated pair genuinely triggers `game::advance_turn`'s
round-wrap check, which calls `game::finish_game` and flips
`state.game_over` to `true` -- correctly. `replay_game`'s own
`if r.state.game_over { break; }` guard then fires on the SECOND duplicate
line, one line before the file's own "End of game" text is ever reached --
so `completed` (set ONLY by literally reading that line) stays `false`
forever, even though the engine's own state is already correctly finished.

--------------------------------------------------------------------------
WHY THIS WAS NOT A ONE-LINE FIX (confirmed by tracing, not just trusting
the warning)
--------------------------------------------------------------------------
`game::finish_game` calls `events::evaluate_final_events(state)`
UNCONDITIONALLY as part of flipping `game_over` -- it reads whatever is
currently sitting in `state.current_events`/`state.future_events` (this
reconstruction's own FICTIONAL filler piles, per `event_plan`'s own module
doc: "filled with unused cards of the right age and kind", "nothing ever
validates them" for final-scoring purposes) and adds the resulting culture
delta into `p.culture` immediately, once, right there.

For all 222 working games, "End of game" is read BEFORE the real trailing
End Turn line, so `ground_final_events` (replacing the piles with the real
cards the log names) runs BEFORE `finish_game`/`evaluate_final_events`
ever reads them -- correct by construction.

For the 68 broken games, the ORDER IS REVERSED: `finish_game` already ran
-- and already baked in a WRONG culture delta computed from the fictional
piles -- one or two lines before the real "End of game" marker is even
reached. A naive `completed = true` flip at the `game_over`-guard break
site would recover the COUNT but ship WRONG scores (verification
theatre, not real verification) -- exactly the failure mode this task said
not to produce.

--------------------------------------------------------------------------
THE FIX (rust/src/replay_common.rs, in the `if r.state.game_over { ... }`
arm just after the "End of game"/"Last turn" handling, replay_game)
--------------------------------------------------------------------------
When that guard fires with `completed` still `false`:
1. Peek at the STILL-UNREAD remainder of the journal (`journal[i..]`, i.e.
   this line onward -- proven never more than 1-2 lines away, GAMEDROP.txt)
   for the real "End of game" line. Not found -> leave `completed` false
   and reject, exactly as before (a genuinely different truncation, e.g. a
   resignation, is NOT waved through).
2. If found: recompute `events::final_event_awards` off the CURRENT
   (still-fictional) piles -- the exact wrong award `finish_game` already
   applied, since nothing else has touched the piles or any player's
   culture in between -- and subtract it back out of `p.culture`.
3. Ground the piles for real (`ground_final_events`, the SAME function the
   working 222's own branch already calls) off the real marker's text.
4. Re-run `events::evaluate_final_events` -- the SAME function
   `finish_game` itself calls -- now against the correctly grounded piles.
5. Only THEN set `completed = true`.

This is gated on `!completed`, which is ONLY ever false before "End of
game" has actually been read -- so for all 222 already-working games this
whole block is dead code (they always have `completed == true` by the time
this guard could fire), which is WHY the 222 are provably, not just
measuredly, unperturbed: the new code path is unreachable for them.
Nothing in game.rs, events.rs, or any file outside replay_common.rs was
touched -- the fix and its correction machinery live strictly in the
replayer, same file as the pre-existing "End of game" grounding branch.
