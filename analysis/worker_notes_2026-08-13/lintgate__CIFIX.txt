CIFIX.txt -- making the new CI workflow (.github/workflows/ci.yml) actually GREEN
====================================================================================

Starting point (from LINTGATE.txt, the previous worker's own honest gap #1):
the wildcard-match gate (rust/Cargo.toml's [lints.clippy]: wildcard_enum_
match_arm / match_wildcard_for_single_variants / wildcard_in_or_patterns, all
`deny`) was already fully clean. But ci.yml runs `cargo clippy --all-targets
-- -D warnings`, which promotes EVERY clippy/rustc warning (not just the
wildcard family) to a hard error, and ~72 pre-existing, unrelated findings
were red from day one. This task's job was to clear those without touching
the wildcard gate or changing program behaviour.

Commit landed: 1e97600 "Make rust CI green: fix the ~72 pre-existing clippy
findings under -D warnings" (43 files changed, on top of 50d6c85/9691e61).


1. METHOD
---------

- `cargo clippy --all-targets --fix --allow-dirty --allow-staged`, run
  repeatedly until it stopped changing anything -- fixed one real compile
  blocker (erasing_op false structure) after a manual one-line fix let it
  proceed further, plus a handful of trivial suggestions.
- For everything --fix declined to touch: parsed `cargo clippy --all-targets
  --message-format=json`, grouped by lint code + deduplicated by (file,
  byte_start, byte_end) primary span, and applied every MachineApplicable
  suggested_replacement by direct byte substitution (same technique
  LINTGATE.txt used for the wildcard enumeration) -- 48 edits across 16
  files in one pass. This is compiler-verified text, not paraphrase.
- One of those machine-applicable edits (blocks_in_conditions in
  replay_common.rs) omitted required braces around an `else` arm and broke
  compilation; fixed by hand (added the two missing braces, no logic
  change) -- see section 2.
- Everything else (needless_range_loop's HasPlaceholders suggestions,
  type_complexity, too_many_arguments, large_enum_variant, module_inception,
  a few others with no machine suggestion at all) was read and fixed or
  `#[allow]`'d by hand, one group at a time, largest first.
- Verified after every group: `cargo build --all-targets` (fast fail on
  anything broken), full `cargo clippy --all-targets -- -D warnings` at the
  end, then `cargo test`.

3. EVERY #[allow] ADDED, AND WHY
----------------------------------

Each is scoped to a single item (function, loop, or enum) with an inline
comment explaining the specific conflict -- never a file- or crate-level
blanket allow.

  clippy::large_enum_variant x2
    - bots/greedy.rs `Search` enum: boxing the large variant would make
      `Search` (and therefore `Seat`, which embeds it) no longer `Copy` --
      and `Seat`'s own doc comment right above documents that `Copy`-ness as
      load-bearing ("should not cost a `.clone()` at every call site").
      Trading that away is a real behaviour/API change.
    - bots/neural/spec.rs `ClassicalPlayer` enum: boxing `Quiescent`'s or
      `Plan`'s fields would require touching every match arm across the
      crate that destructures those variants directly -- already fully
      enumerated per the wildcard-match ban, so this ripples further than a
      lint-only fix should.

  clippy::too_many_arguments x13 (bots/neural/policy_train.rs,
    bots/neural/train.rs x2, bots/plan.rs x6, bots/quiescent.rs,
    harness/play.rs, harness/record.rs, replay_common.rs)
    Grouping into a config struct is the real fix clippy wants, but it's a
    cross-cutting refactor -- every call site of each function would need
    updating too. Out of scope for a lint-gate pass that must not change
    behaviour; each argument list is otherwise stable and unambiguous at
    every call site.

  clippy::needless_range_loop x8 (bots/neural/train.rs x6,
    bots/neural/policy_train.rs x2, bin/agreefit.rs x2 -- 8 distinct
    #[allow] sites, agreefit counted separately below)
    Actually: bots/neural/train.rs (6) + policy_train.rs (2) + agreefit.rs
    (2) = 10 sites total allowed (the other 3 of the original 13 were fixed
    for real -- see section 2). These are dense training-math loops
    (forward/backward pass, layer-norm stats, dropout masks, softmax
    gradient descent) indexing several parallel arrays or self-fields
    together (some behind `&mut self.field[i]` on two different fields at
    once). A hand-written zip rewrite here is real engineering with a real
    failure mode: a misaligned index would silently produce wrong gradients
    with no compiler error and no likely test failure (the test suite
    checks pass/fail behaviour, not exact gradient values at this
    granularity). Not worth that risk for a style lint on numerically
    sensitive code with no reference to check against.

  clippy::while_let_loop x1 (interact.rs settle_war_spoils)
    The suggested `while let Some(...) = state.pending.top() { ... }`
    rewrite keeps the immutable borrow from `top()` alive across the loop
    body, but the body calls `apply_pending(state, ...)` which needs `state`
    mutably -- this does not actually compile as clippy suggests. The
    existing `loop { match ... { Some(...) => n, _ => break }; ... }` shape
    exists specifically to extract just the `usize` and drop the borrow
    before the mutable call.

  clippy::neg_cmp_op_on_partial_ord x1 (stats.rs Estimate::p_against)
    `if !(self.se > 0.0) { return 1.0; }` is a deliberate NaN guard: for
    `se.is_nan()`, `!(se > 0.0)` is true (correctly triggers the early
    return), but clippy's suggested `se <= 0.0` would be FALSE for NaN
    (comparisons against NaN are always false), silently changing behaviour
    by falling through to divide by a NaN `se`. Kept the negated form,
    allowed the lint, documented why.

  dead_code x1 (bin/humanwinners.rs PlayerAgg::color)
    Genuinely unread today (every reader gets the colour from the
    `HashMap<Color, PlayerAgg>` key instead) but removing it means dropping
    the `new(color: Color)` parameter too -- churn with no behavioural
    upside for a lint-only pass. Allowed with a comment.
