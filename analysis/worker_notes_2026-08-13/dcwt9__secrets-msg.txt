Move the rescue credential out of the tree git can see, and cover the four refresh rules that each cost a real token

credentials.oauth_stash() wrote the whole keychain blob — access token AND
refresh token — to STATE_DIR/.refreshed-credential.json, and STATE_DIR
defaults to BASE_DIR, which is this checkout. The docstring called it alive
only between the POST and the read-back; that is the happy path. The branch
that KEEPS it is "keychain write FAILED, credential kept in {stash}", so it
lingers exactly when something has gone wrong, indefinitely, in a repo that
agents commit from.

The stash now lives in STATE_DIR/.secrets/. Not somewhere outside the
checkout entirely, which was the first instinct: $HOME on this machine is
itself a git repo (ptarjan/dotfiles, PUBLIC), so ~/.claude would move a live
credential from a private tree to a public one's working directory, and the
CLI's own keychain is macOS-only — refresh_oauth_login cannot run anywhere
STATE_DIR is not a Mac's checkout anyway. A directory of its own is what one
ignore rule can cover no matter what the file inside it is later renamed to,
which is the drift that had already happened once.

The ignore list was a hand-typed copy of config.py's literals. Nothing
derived it, so renaming the stash left the whole suite green with the new
name uncommittable by nothing. StateDirIgnoreTests now walks the
STATE_DIR/BASE_DIR paths out of config.py's AST, adds oauth_stash() by
CALLING it, and asks `git check-ignore` about each — with a floor under the
walk, since a derivation that resolves to nothing satisfies every assertion
made over it. It touches no disk and works in a worktree.

Two more holes closed at the write itself: the parent directory is created
0700, and the stash is unlinked before touch(0o600), because touch does not
narrow the mode of a file that already exists and one exists precisely when
the last refresh failed.

refresh_oauth_login and _keychain_login had zero coverage, and four of their
rules cost a refresh token when wrong: picking the newest keychain entry
rather than the husk this Mac has accumulated, writing back the ROTATED
refresh token rather than the spent one, refusing to believe a keychain write
that came back short (the 128-byte truncation, which also unlinks the rescue
copy on the way out), and reporting a genuinely 0% usage window instead of
dropping it. All four are covered now, plus the clamp on the level and the
"never refresh a token that is still alive" race rule. Both seams are faked —
credentials._run for the subprocess, urlopen for the HTTP — so nothing here
runs `security` or reaches the network, and every credential in the file is
an obvious fake.

Each of those rules was re-broken to check the tests see it: 11 mutations,
10 caught. The survivor is a rename of the stash file INSIDE .secrets/, which
is not a defect but the reason the rule is a directory — the coverage follows
the rename. Moving it back out of .secrets/, or deleting the ignore rule,
both fail.
